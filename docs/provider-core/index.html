provider-core

provider-core is the locally maintained, independently installed NMR API provider package. It owns signing, transport, Upload access, durable Attempt lifecycle and shared diagnostic facts. Scientific interpretation and execution remain consumer-owned. The dated package record preserves its implementation decisions and qualification limits.

Credential admission

provider_core.credential.parse_provider_credential(raw) admits the original API-issued signing.private.json bytes: provider v1 schema, seven text fields, canonical JSON followed by one newline, the frozen deployment profiles and a matching Ed25519 public/private key pair. The returned immutable credential hides the private key from repr; CredentialRejected exposes owned operation context and keeps original decode evidence in its private cause. Startup owns file permissions, intended profile/provider binding and credential lifetime. This parser neither reads ambient files nor issues or registers a replacement key.

The parser ports SECS's credential admission to core's bounded JSON and shared reference owners. The API's artifact issuer and provider/private_signing_v1.py own the fields and profile vocabulary. make test/unit/provider-core/credential runs focused artifact/signing tests against the installed package, offline and without consumer source mounts.

Runtime requirements

The package requires Python 3.12 or later. This repository runs it on Python 3.12.12 in Linux x86-64 containers through the maintained launcher. Python 3.11 is outside the declared support range. The package metadata declares the full runtime dependencies, installed by default:

  • cryptography==50.0.0
  • http-sf==1.2.1
  • httpx==0.28.1
  • httpcore==1.0.9

Use the complete hash-locked runtime closure for this repository's contained installation. The build uses setuptools 84.0.0. Dependency rationale records the selected versions and dated security review. Identify a deployed wheel by its exact bytes and source revision; the package version alone does not identify a build.

Run through a maintained container launcher that sets PROVIDER_CORE_IN_CONTAINER=1. The marker prevents accidental host execution; the launcher owns actual filesystem, network and process isolation. Lifecycle operations, storage and their shared claim registry run on one asyncio event loop. Scientific workers, their protocols and deployment policy remain outside this package. The plan note records implemented behavior and remaining limits.

Diagnostic ownership

provider_core.failure_projection.owned_details(error) returns fresh scalar facts for exact reviewed core exceptions. owned_relationships(error) yields labelled references to their original causes, cleanup failures and interruptions, including absent or repeated causes. Both are protected, unredacted inputs to the caller's reporter. Unknown types and subclasses expose nothing. Responses, other headers and scientific payloads are excluded; admitted status/request IDs and received/in-memory facts do not establish durable acceptance.

ExecutionFailed retains its existing acknowledged Attempt so the operator's report can identify the affected Job and Attempt even when preparation fails before scientific work starts. Its projection exposes only those two references; the acknowledgement is private context, not proof of dispatch or a terminal receipt. Failures before an Attempt is acknowledged do not acquire an invented ID.

NMRNet consumes these functions in its existing process_reports.py reporter. That reporter still owns the one mixed causal graph, ordinary Python chains and groups, cycle/display bounds, credential redaction before bounds, scientific summaries and recipient sinks. Core adds no graph walker, formatter, journal or public disclosure policy. make test/unit/provider-core/diagnostics checks the shared owner facts; make test/integration/provider-core/process checks actual protected diagnostic delivery through NMRNet. In the running service, stdout and stderr go to bounded Docker logs; there is no parallel diagnostic-file export. Operator diagnostics explains access and retention. API result/failure delivery and diagnostic-history retention are separate claims; their dated evidence is in 003's API delivery record and the logging decision.

Directory announcements

ProviderAPI.publish_hello(provider_ref=..., display_name=..., description=..., analysis_offerings=(AnalysisOffering(...), ...)) sends one complete current directory announcement through the existing signed transport. Import AnalysisOffering from provider_core.hello. Empty offerings withdraw the advertised set; omissions remove old entries. The returned HelloAccepted contains the expected provider reference and the server's acceptance time. It establishes announcement acceptance then, without claiming scientific readiness or that another publisher has not since replaced it.

No failed Hello is retried automatically. ApiFailure retains private transport or response evidence; its safe notes explain that acceptance is unconfirmed and the directory may already have changed. Cancellation remains cancellation, with the same context in api.last_failure. Composition owns transport settlement and decides whether its latest complete announcement is still intended before another send. Hello creates no durable Attempt/replay record or Attempt-effect flag.

After retiring the original exchange, can_refresh_hello(failure) permits composition to construct a new current Hello for reviewed availability failures. It requires this API's current failure and the exact signed Hello POST target, without a query. It grants no replay permission to another POST and does not establish that the failed announcement was accepted. The caller must rebuild from current state; this predicate does not retry or retain a body for replay. NMRNet's service supplies that policy, with stop-aware capped backoff and a fresh announcement supplier call on each send. Initial acceptance gates allocation; periodic Hello recovery runs independently of the active scientific Attempt.

Observation recovery

Core's AttemptController and AttemptExecutor accept an optional execution.ObservationRecovery(gap_seconds, backoff_max_seconds, on_retry, on_recovered). None keeps their fail-stop read policy. A supplied policy permits only reviewed active-Attempt GET recovery after original transport retirement; it grants no progress, START, terminal-publication or science retry. Observers receive the borrowed acknowledgement and protected original failure; retry also receives its jittered delay. They must finish synchronously within a bounded time.

Each fresh-observation wait includes exchange-lock acquisition, I/O, retirement and capped backoff. Deadline expiry starts scientific retirement independently of read cleanup. The original observation waiter stays owned until settlement, which cannot accept its late response as permission to resume science. A completed result still requires a fresh allowed observation before terminal selection. Expiry keeps the existing suppressed-evidence path and does not itself authorize publication or another Job. ObservationGapExpired distinguishes a read that started from waiting for exchange access and projects the same window's late-arriving cause. NMRNet's production factory requires enabled recovery before allocating workers; its configured gap and process notice callbacks reach this same policy. The operator guide describes the required setting and protected notices. Local signed-TLS tests qualify that wiring, not deployment.

Wire authority is the pinned API's PROVIDER_HELLO_ROUTE, provider/schemas/hello_{request,response}.v1.schema.json and operations/provider_directory.py::ProviderHelloCommand (duplicate kinds). Construction and receipt admission adapt SECS's Hello helpers to core's existing reference, bounded JSON, UTC timestamp and failure owners. The synchronous publisher/retry loop is not copied. Focused installed-package proofs: make test/unit/provider-core/hello and make test/integration/provider-core/hello; the latter uses only local TLS and API-shaped disposable credentials, without consumer sources or deployed API access.

make test/contract/provider-core also checks the complete pinned public API release consumed by NMRPeak: its inventory, both published signing vectors, and all eleven provider dispatches against released routes, byte ceilings and closed top-level fields. It verifies emitted signatures against the released signature bases using a fresh test key, and the published signatures using their public keys. Hello scalar limits, topology names, exact Job bytes and noncanonical Base64 refusal are tied to the same artifacts. Future response versions/fields refuse before returning admitted facts. The fixture provenance records exact source and content identities. These focused consumed-rule tests do not implement a schema engine, attest the publisher or establish a live server's supported release; actual consumer/deployment compatibility remains separate.

The supported test targets run offline in containers. The runtime launcher must set PROVIDER_CORE_IN_CONTAINER=1; this accidental-host-execution guard does not attest to isolation. The host/container composition owns actual grants.

Source contracts: nmr-api-v1 at 6a163b7a9cc1e2c7485b681c0b2b969c7c20e6c8, nmr_api/provider/schemas/job_input_read_response.v1.schema.json and nmr_api/job_specification.py; Magnet at c5813ee35cfbb1c98a5cc5d20a94787271f26486, magnet_provider/job_input.py. Exact Job bytes are preserved before science-specific admission. The verifier binds caller-supplied observations; it does not authenticate a network peer or grant authority.

Signing follows the API's RFC 9421 profile and credential syntax. Request construction adapts Magnet's signing implementation: Ed25519, exact method/authority/path/query, a digest for every supplied body, 16-byte nonce and 300-second expiry. Time and nonce generation belong to the API operation caller. HTTPX target rewriting is rejected before sending. A constructed signature is not evidence that a server accepted a request.

Transport and settlement

HttpTransport owns one serial HTTPS exchange at a time and uses a fresh client for each. It disables redirects and ambient proxy/auth configuration, bounds raw response bytes and the total exchange duration, and allows a separately configured finite retirement grace. Composition supplies verified TLS trust and must await retire() before shutdown or replacement. Pending or failed closure blocks reuse; process retirement remains the fallback authority when closure cannot be confirmed. This deliberately trades connection pooling for simpler ownership. It follows Magnet's exchange boundary, but retains cleanup failures instead of adopting its best-effort release policy. exchange_file(..., output_fd=...) streams the response into a caller-owned writable regular-file descriptor without append mode, at its current position. It admits that descriptor before sending the request and returns HttpFileResponse with received status, headers, byte length and SHA-256, without a buffered body. These describe this response's bytes, not the whole destination or a verified Upload. The caller must keep the descriptor open and unchanged until transport retirement is confirmed, including after cancellation or deadline expiry. The transport stops network I/O and settles the original pending disk write before releasing ownership; it never closes or deletes the caller's file. Failed or cancelled exchanges may leave partial or complete response bytes in the file; their presence does not admit an Upload. Grant verification, file finalization and reader-safe cleanup remain acquisition and composition responsibilities. HTTPcore's public network backend retains each TCP stream before TLS begins, so cancellation during the handshake cannot leave a socket outside cleanup's ownership. HTTPX constructs requests; HTTPcore performs the exchange without automatic redirects or ambient proxies. Native I/O exceptions remain protected causes, not a public promise of HTTPX exception types. An explicit proxy_socket selects HTTPS CONNECT over one absolute Linux Unix socket path (at most 107 UTF-8 bytes). The backend never resolves or connects to the destination directly in this mode. HTTPcore owns CONNECT and destination TLS; the original URL, Host, signature and TLS name remain unchanged. Credentials remain inside destination TLS. No proxy socket means the existing direct route. IPv6 literal destinations are refused before I/O in proxy mode: pinned HTTPcore 1.0.9 constructs an unbracketed CONNECT authority for them. DNS names and IPv4 literals are supported. This transport seam does not grant or attest to a proxy's destination policy, network isolation or interface binding; those belong to the host composition. Local Unix/TLS tests prove routing, certificate rejection, deadline/cancellation cleanup and no retry after a lost POST reply. ExchangeFailed exposes safe text; its original causes and interruption evidence are for protected diagnostics and must not be rendered directly to users. Its private response_head retains received status and raw headers when body streaming or cleanup fails. Headers remain hidden from repr; no partial body is returned as HttpResponse. The same failure gains later observations when its owner settles unfinished I/O. Received headers do not confirm API acceptance or authorize another operation. API topology/correlation admission uses this evidence at the API boundary; chat and store transports do not interpret API headers. make test/unit/provider-core/transport checks ownership, cause retention and late metadata, including cancellation-resistant cleanup. make test/integration/provider-core/transport checks actual local TLS truncation and body timeout without granting consumer sources. This metadata boundary adapts the diagnostic preservation in SECS's response reader; the pinned HTTPcore HTTP/1.1 parser continues owning framing. No dependencies or transport budgets changed.

Interpreter conversations

provider_core.chat supplies ChatEndpointSpec, ChatEndpoint and ChatFailed for Chat Completions tool turns. Composition supplies the complete HTTPS URL, model, key, optional reasoning effort, dedicated HttpTransport and explicit request/response byte limits. One call sends one POST and admits one complete assistant reply. It never retries a lost reply. The consumer owns prompts, tools, argument admission, corrections, endpoint selection and the conversation budget. Composition must await retire() before replacement or shutdown; unresolved retirement remains owned. No ambient credentials or endpoint defaults are read.

Endpoint identity contains safe configuration/model IDs and a hash of request configuration, excluding the key. It does not identify the whole TLS policy or conversation. URL/key are hidden from repr. ChatFailed has safe operation text; raw response bytes and underlying causes remain private and may contain secrets or source text. Never put them in model feedback or public results.

The boundary follows Magnet's chat adapter: separate endpoint facts, HTTP exchange and conversation decisions. This adapter was written here, reusing core's stronger retirement owner rather than copying best-effort cleanup or provider-specific retry policy. It has no scientific or repository imports. make test/integration/provider-core/chat builds and tests the installed wheel against local TLS peers without mounting consumer sources; this proves carrier behavior, not external model interpretation.

provider_core.conversation.ToolConversation keeps serial tool turns and bounded endpoint fallback in one transcript. Callers supply an ordered endpoint tuple, one total turn limit, known endpoint keys and a dispatcher. ToolReply continues, ToolFinished ends, and only ToolRejected requests correction. Scientific and publication policy remain with the binding. Each attempted exchange consumes a turn; fallback requires confirmed retirement and carries completed tool results forward. The caller owns the aggregate deadline and run-task cancellation.

Only admitted assistant fields enter later requests. Rejected argument text is discarded, decoded arguments are checked for configured credentials, and tool feedback must be an owned safe projection. These checks do not classify arbitrary scientific text as public. The returned immutable observation contains tool/config identities, route counts and safe failure summaries, without a transcript. Original endpoint failures remain transient private endpoint_failures; cleanup retains the failed operation and independent retirement failures. Await retire() after every outcome; a retired conversation cannot accept a late decision.

The shared transcript/correction boundary follows SECS's interpreter. This independently written loop retains completed effects across fallback instead of restarting scientific preparation. It imports no molecular tools, report precedence or scientific schema. NMRNet's binding supplies those decisions.

Job and Attempt API

ProviderAPI(identity, transport, expected_topology=configured_topology).job_input(feed, analysis_kind_ref=...) performs one signed read and returns VerifiedJobInput. The caller must obtain feed from an authenticated source; constructing FeedInputFacts only checks its shape. The method admits the pinned response headers and delegates byte/identity checking to the existing verifier. It neither interprets instructions nor retries failures. Composition owns the supplied transport and its retirement.

Every API client requires an explicit expected_topology: dev-local, dev or web, independently of credential profile. Responses must contain exactly one matching Nmr-Api-Topology, the route's content type and no-store, without content encoding. A valid singleton X-Request-ID remains available on ApiFailure.request_id even when environment/body admission fails. Invalid or duplicate IDs provide no trusted correlation; problem replies require a valid ID. Reviewed problem meaning additionally requires matching header/body request IDs. Success request IDs remain optional. Status/correlation read from the actual response or its retained transport cause, so late metadata becomes available without copying stale facts. It cannot retroactively verify a problem code or reduce issuance/Attempt uncertainty after failed I/O.

ProviderAPI.can_retry_read(failure) permits another GET only for that API's current exchange-owned failure after transport retirement is confirmed. Reviewed timeouts/native connection failures and HTTP 502/503/504 can qualify. A proxy may return HTML or omit API metadata during an outage: permission to repeat the read does not admit that body, establish transience or verify a Problem. Explicit wrong/duplicate topology, authentication rejection, malformed success, TLS/protocol defects and unknown I/O causes do not qualify. Hello and other mutations never qualify. Composition still owns paced backoff, stop handling and useful diagnostics; the predicate sends nothing and does not repeat an operation automatically.

This boundary follows SECS's response admission. Authority: the pinned API's edge_topology.py, entrypoints/_edge_runtime.py::send_with_topology, request_ids.py and security/problems.py. Focused proofs are make test/unit/provider-core/api and make test/integration/provider-core/api; no external API is contacted.

ProviderAPI.jobs(analysis_kind_ref=..., has_provider_execution_attempt=..., limit=..., cursor=...) reads exactly one signed discovery page. All choices are explicit; pass cursor=None for the first page. Returned immutable Job items carry the existing FeedInputFacts for job_input(), plus their creation time. Kind/view echoes, field shapes, identities, calendar values and the requested page size are admitted before any item is returned. Unknown fields/schema versions fail explicitly. The whole response is bounded to 65536 bytes; at most 100 items are admitted.

The false presence view lists selected open Jobs with no prior Attempt by this provider. The true view means a prior Attempt in any state; it is not an inventory of currently running work. Composition still owns pagination, selection, claims and fresh state checks. Core validates only the cursor's canonical base64url representation; the server binds its opaque contents to the provider/kind/view. No automatic follow-up request or retry occurs.

Authority and rationale: the pinned API's discovery route, response schema, request parser and visibility service own these facts. This operation supplies authenticated observations to the existing input owner; a second discovery client in each binding would duplicate signing and wire admission. Local TLS tests prove the connection, not deployed visibility.

ProviderAPI.execution_attempts(state="in_progress", limit=..., cursor=...) reads one signed inventory page for the authenticated provider principal, across analysis kinds and restricted to visible Jobs. All three choices are explicit; pass cursor=None for the first page. The immutable page preserves server order, Attempt/Job/kind identities, provider attempt key, state and original start time. It admits the exact schema, canonical timestamps/cursors and requested count, within the API's 100-item and 65536-byte response ceilings. Keys and cursors stay out of repr. Shared paging owns the same wire grammar used by Job discovery.

Inventory is a live observation. A separate read_attempt() binds a fresh point read to the selected Attempt/Job identities and obtains Job state; inventory contains no Job state or terminal receipt. Cursors remain opaque and bind to the provider principal and fixed view on the server. No automatic pagination, retry, claim, resume or abandonment occurs. An absent row does not prove that an Attempt never existed or that execution/publication completed. Traversal can change while work progresses; composition owns its request/time budget and recovery policy.

Authority and rationale: the pinned API's inventory route, request parser, response schema, cursor owner and visibility service define this distinct recovery input. Local TLS tests prove signed transmission, identity-preserving current readback and original-owner retirement, not deployed visibility or a production recovery decision.

ApiFailure carries safe operation text, HTTP status when received, valid header request correlation when available, and a reviewed problem code when verified. Original response and cause remain private for authorized diagnostics. Unknown server text is retained there, not displayed. Cancellation remains CancelledError; ProviderAPI.last_failure retains its operation context and transport evidence. Downstream recipient projections remain unfinished composition work.

Wire and diagnostic rationale: the API's exact Job-input route, catalog-key grammar, problem vocabulary and request correlation syntax control this boundary. Local finite-TLS tests establish transmission, socket closure and exact-byte admission; they do not establish deployed API acceptance.

ProviderAPI.uploads(job_ref) returns an immutable UploadSet bound to the requested Job. It preserves descriptions, ordering and pending content hashes. read_grant(job_ref, upload_ref) makes one bodyless POST and returns an inert ReadGrant. Its Job reference records request context; the API response itself only echoes the Upload reference. Resource identity is distinct from content hash. These methods do not contact the Upload store. The subsequent acquisition owner must check configured store origin/path, current membership, expiry and byte facts.

A failed grant request can already have extended Upload retention. The failure's issuance_may_have_committed is conservative current-call evidence, including on cancellation via last_failure; it does not resolve any earlier request. Recognised authentication refusals and the exact unfinished-Upload/Project-purge refusals establish no new issuance. Generic 403/404, unavailable replies, malformed grants and transport failures remain uncertain. No request is retried automatically. The API's grant service and specific refusal contracts establish these distinctions. Bearer, URL and descriptions stay out of record repr; they are private data, not public diagnostics.

JobUploads(job_ref, api=..., store=..., store_origin=..., limits=UploadLimits(...)) owns one source session. Call inspect(), select an Upload reference, then call acquire(ref) for immutable VerifiedUpload.data. Acquisition refreshes the whole observed membership, requires explicit reinspection/reselection after a change or failure, obtains a fresh grant, and checks identity, byte facts, expiry and exact configured store target before sending a bearer. It has no byte cache or implicit retry. Pending membership hashes can be finalized by the grant. Changes after the last membership observation cannot be atomically excluded by the API.

acquire_file(ref, directory_fd=..., retirement_seconds=...) uses the same selection, grant and byte checks while streaming to a file. Composition lends an open, exclusively controlled mode-0700 directory owned by the running process's effective user. Acquisition creates one exclusive mode-0600 file before requesting a grant, verifies the whole transfer and observes its close before returning VerifiedUploadFile. Its hidden-from-repr name is a basename relative to that directory; the receipt carries the same Job, Upload, length and hash facts as the byte result. A worker must verify an immutable snapshot against those facts before parsing. The receipt establishes no future pathname integrity or storage durability. Composition owns successful files and must confirm reader quiescence before deletion.

read_upload_file(receipt, directory_fd=..., maximum_bytes=...) is the matching synchronous reader boundary. Call it inside an already supervised worker, using the receipt's basename in the explicitly granted directory. It opens once without following a symlink, requires a regular file, copies at most the expected length plus one sentinel byte in chunks of at most 65536 bytes, and verifies the immutable copy through VerifiedUpload. It observes descriptor close before returning that byte result. Parse only its .data, including any archive sniffing or member reads; never hash a mutable descriptor and then seek or reopen it for parsing. Later path or file changes cannot alter the returned bytes. This is a verified byte copy, not an atomic filesystem snapshot, constant-memory operation or durability proof.

UploadFileReadFailed names this read/verification operation and carries protected cause, cleanup and interruption evidence, without acquisition/grant-issuance facts. A complete copy with unconfirmed close is refused. Close is attempted once; composition must confirm worker retirement before releasing the source after an uncertain close. A cancellation raised inside the worker's read remains the original exception with linked evidence if close also fails. Interruption of an awaiting controller and actual worker stop belong to the supervising owner. The worker's explicit byte ceiling is operational configuration here; user-facing fixed source capacity is admitted by JobUploads before grants. This primitive provides no new async executor, parser, network authority or archive policy. Existing NMRNet readers already receive immutable bytes; adopting this file seam and qualifying ZIP/peer workers remain separate.

The installed Upload integration lane also checks a local proposed SECS receiving adapter in tests/fakes/secs_sources.py. It ports the pinned source-access contract with immutable views for both direct files and archives. Member/count/listing and expanded-byte limits, scope debits and decoder-error classification stay with that consumer. Its scratch directory remains separate from the acquired-source directory_fd: the existing format consumer uses it for fixed-name temporary files. This fixture qualifies the receiving seam against the installed core, without importing a sibling checkout at runtime. It does not establish actual SECS adoption, Job admission, worker retirement, decoder science, memory capacity or the rest of the async consumer contract.

Keep the lent directory descriptor open and unchanged until success or confirmed failed-file cleanup. An interrupted acquisition retains its original file I/O and blocks further source work. First retire an outstanding store exchange with this JobUploads as its owner, then await settle_file(). Settlement continues abort cleanup only: it never issues another grant, resumes a download or returns a late receipt. It uses the cleanup grace supplied to acquisition even after the source deadline expires. A failed close is never retried by descriptor number; unconfirmed closure requires enclosing-process retirement. An unknown original file identity or a changed directory entry prevents automatic deletion and requires inspection of the composition-owned source directory. An observed replacement is left alone; cleanup never infers original identity from its pathname. Confirmed absence permits later settlement. This relies on exclusive directory control, not an atomic conditional unlink against a concurrently mutating same-user writer.

Limits cover per-source bytes, total consumed store-body bytes, total requests and elapsed session time. Inspection, refresh, grant and transfer share the request and time limits. Metadata uses its separate API route byte ceilings. Failed and cancelled downloads retain consumed-byte charges; an offending received chunk is counted even when it exceeds the limit. This is application-body accounting, not an operating-system network-traffic quota. acquire keeps response bytes in private memory under the supplied limits until status, headers, length and SHA-256 pass; it uses no staging directory. acquire_file writes only into the explicitly lent private directory. Creation and final-close waits share the source deadline without consuming request slots. The final deadline check rejects late verification or finalization results. Byte-result hashing is synchronous and bounded by the per-source limit; it is not preempted mid-hash. Transport and file cleanup grace remain separate from the source-work deadline. Neither output refunds failed work.

The API and store use distinct supplied transports. Store requests carry only the bearer, never provider signing material; redirects are not followed. Composition owns both transports' retirement. retirement_confirmed exposes the transport's actual ownership state, and an unresolved store retirement blocks source work. UploadFailed.cause, cleanup_failures and interruption are protected evidence. Cleanup evidence is bounded to the latest observed failure; another polling timeout does not erase a concrete filesystem failure. It may remain available after later settlement confirms cleanup, and supplies no lifecycle authority. grant_issued records successful issuance before a later failure; uncertain issuance remains in the underlying ApiFailure. Caller cancellation still propagates, with evidence in last_failure.

The exact store response contract comes from pinned API upload_transfer_http.py and upload_transfer_http_contract.py. Membership→grant→verified bytes follows the source-ordering precedent in SECS job_api.py and upload_download.py. The local implementation is async and introduces shared session accounting; it does not import sibling code or claim sibling migration.
