Source and provenance limits

The copy came from NMRPeak's pinned contract bundle. It matches the API's archived release byte for byte. The archive commit records this existing source provenance.

Content identity does not authenticate the publisher. The declared source_revision is excluded from the release-reference digest and is not cryptographically attested. These snapshots do not establish a live server's supported baseline: contract_releases/checks.py, inspected at API revision e7790cf6a922c39261fe736d5a23d17a9a5ea322, explicitly selected no supported historical baseline.

What the tests consume

Tests adapt tests/unit/test_provider_signing.py and the artifact/hash rules in nmrpeak_provider/provider_http_contract.py at the pinned NMRPeak revision above. The complete bundle keeps signing vectors, schemas, route facts and their original inventory together.

This is test data, excluded from the runtime wheel. Contract tests check specific consumed rules; they are not a general JSON Schema validator or exhaustive OpenAPI qualification. No sibling source is imported at runtime and no schema-engine dependency is added.
