Priority correction: 2026-10-17
===============================

Author: repository coordinator. Purpose: align the remaining work with the
maintainer's confirmed goal: a reproducible, contained NMRNet++ provider for
the NMR API. The coordinate callable is an enabling milestone. A standalone
file CLI and a separate prediction-result publication workflow are deferred;
their previous requirements no longer define completion of 002. The prior
design and its review rationale remain in the committed note:
https://github.com/numpde/nmrnet-repro/blob/c8b26e651a0753d0e1e6375240bab25b1e8f4da1/notes/002_label_free_coordinate_prediction_20261014.txt
This is an explicit scope correction, not evidence that an unimplemented gate
has passed. Scientific qualification, containment, resource bounds and useful
safe error propagation remain requirements. Implementation was paused during
that plan/README-only correction and resumed on 2026-10-17; see the construction
update below.

Priorities, in dependency order:

1. Establish the provider-facing input/result/failure boundary from the current
   API and sibling code. Decide what molecular information the offering accepts
   and how it reaches the coordinate callable; record unresolved chemistry
   choices before adding transformations or a new transport. This investigation
   runs alongside model integration so later callers shape the implementation.
2. Connect verified dictionary/checkpoint/scaler bytes to the real registered
   model and head, without task/dataset/loss setup. Exercise real predictions
   on the pinned reference fixtures in the existing contained scientific lane.
3. Qualify numerical overlap, complete atom coverage, reuse, maximum admitted
   workload and safe failures. The repository adopts ångströms for H/C model
   inputs based on the documented evidence and bounded geometry check below;
   retain the evidence limits in the public input contract.
4. Deliver the qualified callable and compact evidence needed by the provider.
   Use the next big slice, 003, for provider integration against the established
   contract, including its container lifecycle and recipient-specific errors.

Source-based rationale for the provider boundary
-----------------------------------------------
Read-only investigation on 2026-10-17 examined magnet-deploy revision
c5813ee35cfbb1c98a5cc5d20a94787271f26486 and nmr-api-v1 revision
6a163b7a9cc1e2c7485b681c0b2b969c7c20e6c8. These are inspected precedents,
not new runtime dependencies or a decision to copy their whole frameworks.

Magnet's ProviderAnalysisProcessor receives verified Job input and returns an
analysis outcome; generic provider code owns Jobs, Attempts and publication.
G01's model worker loads once and serves serial requests over a private socket.
These owners show why an inference callable and its actual provider adapter
belong on the path; a standalone file CLI/publication protocol is not required.
They do not prescribe a socket worker for NMRNet or qualify NMRNet's science:

The API admits user-authored Job specification text; it does not require a
SMILES or coordinate model-input schema. G01's interpreter extracts explicit

result bytes, so the provider should own publication through that contract:

Label-free tensor composition
-----------------------------

`nmrnet_inference/model.py` composes the five CPU tensors for one admitted
ordered atom list and one H or C head. It uses only atom tokens, the element
selection mask, centered coordinates, pairwise distances, edge types, and
right-padding. Requests above 128 atoms are rejected before scientific imports
or pairwise allocation; the adapter does not apply the training dataset's
random crop. Exact dictionary identity/order and coordinate-unit qualification
remain separate gates. The same real-atom selection produces the `select_atom`
tensor and `selected_atom_indices`, a tuple of zero-based input positions in
model-row order. BOS, EOS and padding are excluded, and the mapping stays outside
the five model keyword arguments.

The operation order follows the pinned sources. `CroppingDataset` casts selected
coordinates to float32 (`NMRNetplusplus/uninmr/data/cropping_dataset.py:27-38`),
then `NormalizeDataset` subtracts their per-axis mean and retains float32
(`NMRNetplusplus/uninmr/data/normalize_dataset.py:20-26`). `UniNMRTask` orders
cropping before normalization, creates tokens and element masks, computes
Euclidean distances, adds BOS/EOS borders, and builds edge types
(`NMRNetplusplus/uninmr/tasks/uninmr.py:348-379`). `DistanceDataset` uses the
SciPy p=2 distance matrix and casts it to float32
(`NMRNetplusplus/uninmr/data/distance_dataset.py:13-24`). The task's right-pad
collaters pad each tensor axis to a multiple of eight
(`NMRNetplusplus/uninmr/data/pad_dataset.py:13-47,49-66,88-102`).

The coordinate boundary markers are scalar `0.0` arguments in the upstream
task. Uni-Core's pinned `PrependTokenDataset` and `AppendTokenDataset` create
each marker with `torch.full_like(item[0], token)`, so a scalar marker has the
same three-value row shape as the coordinates
(`https://github.com/dptech-corp/Uni-Core/blob/ace6fae1c8479a9751f2bb1e1d6e4047427bc134/unicore/data/prepend_token_dataset.py#L14-L25`,
`https://github.com/dptech-corp/Uni-Core/blob/ace6fae1c8479a9751f2bb1e1d6e4047427bc134/unicore/data/append_token_dataset.py#L14-L24`). The source pin and archive hash are recorded in
`requirements/unicore-source.json`: commit
`ace6fae1c8479a9751f2bb1e1d6e4047427bc134`, archive SHA-256
`ae240ff27dfc4c698081260d58ce4bee30d4f437fef23bed89d4033625f21583`.
`tests/test_prediction_model.py` uses these
actual wrappers as its oracle and checks exact tensor dtype, shape, and values
for H and C at one and 128 atoms. Its 128-atom fixture uses fractional
coordinates to exercise the float32-before-centering order. It also checks
CPU placement, zero BOS/EOS borders, eight-wide padding, malformed coordinates,
the pre-import and pre-distance 128-atom bound, oversized integers, and
non-echoing unsupported-atom errors. It verifies that selected input indices
match the real rows of the mask for repeated mixed H/C atoms, and that absent
elements have no selected indices or real mask rows. Unsupported-atom errors
report an atom index rather than repeating caller input, retaining an actionable
location without echoing the request payload.

Label-free forward and request orchestration (2026-10-17)
---------------------------------------------------------

`nmrnet_inference.model.predict_element` composes one H or C input, calls the
selected upstream head in evaluation mode with gradients disabled, and requires
one CPU float32 scalar per selected atom. It applies that head's paired scaler
inverse exactly once, checks the returned shape and finiteness, then pairs each
ppm value with the original input atom index from the same mask traversal.
Selection is already performed by the pinned UniMat node-head branch:
`UniNMRTask` defaults to `nmr_head` and registers it as a node-classification
head, and UniMat gathers `model_input[select_atom==1]` before applying that
head. With the task's `num_classes=1`, its result is one scalar row per selected
atom. The loss's later reshape does not perform this selection, so the adapter
validates and preserves the model's selected-row output without masking twice.
The invocation, head registration and output shape follow these exact sources;
inverse scaling follows the loss path:

- https://github.com/numpde/fork-of-NMRNetplusplus/blob/3ba8b9c2f3d0a390d00685d238618345c6ab24d7/uninmr/tasks/uninmr.py#L71-L79

Callable input/result contract
===============================

The existing bounded JSON reader is the coordinate callable's admission
boundary, not an NMR API Job schema or a promise of a file CLI. Qualification
passes one molecule's exact bytes with coordinate_unit, atoms and coordinates.
The provider will need a reviewed mapping from its admitted Job input to this
boundary; this plan does not prescribe how user-authored text becomes molecular
input. Checkpoints, device, precision, masks and model settings remain fixed.
For example:

  {"coordinate_unit":"angstrom","atoms":["C","H"],
   "coordinates":[[0.0,0.0,0.0],[1.09,0.0,0.0]]}

Every request must include `coordinate_unit`. Parsing preserves its exact spelling
and does not default, normalize, rescale coordinates or infer physical meaning.
Before returning, it compares that exact label with the evidence-qualified unit
for each present H/C prediction head; other atoms remain context and do not
select a head. Until a needed model unit is qualified, parsing rejects the
request before model or artifact work. After qualification, only an exact label
match is admitted. Every prediction entrypoint must call this parser before
artifact access and retain the composer's second check before tensor creation.
This keeps the possible training unit open without guessing.

This example illustrates shape only, not a qualified molecule. Caller atom
inventory and order are authoritative: no addition/removal/reordering,
canonicalization, coordinate generation or repairs. These fields do not
establish bond/valence validity.

Proposed admission bounds: at most 1 MiB input bytes, 1-128 atoms and one 3-vector
per atom. These are local resource choices, not learned model chemistry limits.
Read at most the byte limit plus one, then hash and parse the same bounded buffer;
never hash the input path separately and reopen it for parsing. A read-only mount
does not prevent a host rewrite: provenance must identify exactly the bytes used.
In contained scratch, test both an initially oversized source and one that grows
past the limit during reading, with appended bytes available before the reader
reaches EOF. Prove total consumption stays within the byte limit plus one and
oversized input is rejected before parsing. Inject a read failure and keep it an
operational error rather than classifying it as malformed user input. This applies
013 U13's consumed-work and operational-failure guidance; see its cited source
and rationale at
https://github.com/numpde/nmrnet-repro/blob/e6a8a1b1a2dd5cb854d70277f40d3275945ce933/notes/013_sibling_practices_20261016.txt#L176-L184.
Check atom counts and row dimensions before array conversion or quadratic
allocation. Reject extra fields (including
labels or selection-mask overrides), duplicate JSON object keys, unknown atom
symbols and model special tokens. Atom symbols must have dedicated ordinary
chemical-element entries in the loaded dictionary; mapping to UNK is not allowed.
Reject booleans used as numeric coordinates and nonfinite numbers. Check finite
values both before and after float32 conversion: finite JSON/float64 values can
overflow float32. Centering and distance construction must also produce finite
tensors before model execution.

Output has unit="ppm" and predictions ordered by original zero-based atom_index,
each with atom_index, element and shift_ppm. Every H/C
atom appears once; other atoms remain molecular context. Absent nuclei yield no
entries; neither H nor C yields an empty list without an empty-tensor model call.
Hydrogen completeness belongs to the caller. Qualification evidence carries
artifact identities and resource facts; per-prediction entries keep atom identity
and shifts. Provider result/provenance projection belongs to its later adapter.
