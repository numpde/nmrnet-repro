Decision, purpose and completion contract

The product remains a provider of atom-indexed H/C chemical shifts from admitted molecular geometries. Operating it should require a named deployment, its private inputs and a Docker engine, rather than maintaining an application-specific host daemon. Copy the established Compose/container/session-supervisor boundaries; adapt them to NMRNet's existing scientific and durable execution owners.

Target platform: Linux with Docker Engine and Compose v2. Explicit host-interface binding, Unix sockets and the donor supervisor's Linux process facilities are requirements. This is portability between supported Linux installations, not a claim of Windows, macOS, rootless-engine, ARM or arbitrary orchestrator qualification. Preserve the currently qualified image architecture; declare and verify any further platform separately.

  1. A finite deployment command starts the admitted stack, verifies startup and returns. Containers continue after the invoking shell exits and recover after engine/host restart according to their declared policy.
  2. No production component depends on a permanent host Bash monitor, a custom systemd unit, a Docker socket grant or per-Job Docker commands.
  3. One serial provider session owns each runner session. Native child exit and request completion have different evidence. Neither socket EOF nor a healthcheck proves child retirement or successful science.
  4. The existing controller/store remain the sole owners of admission, durable execution entry, retained outcomes and permitted API replay. A container restart creates no new authority to repeat interpretation or computation.
  5. Scientific inputs, atom order, units, conformers, model/scaler selection, full-precision evidence and output formatting retain their existing meaning. Model identity remains tied to the bytes actually verified and loaded.
  6. Ordinary successful Jobs do not exhaust a lifetime allocation counter or accumulate unbounded handles, processes, source files or diagnostic history.
  7. One documented deployment workflow remains after cutover. Obsolete production launchers, selectors, tests and guidance are removed, with historical rationale preserved.

Current implementation and actual changes

At the checkpoint, tools/provider.sh::provider_host_monitor repeatedly services provider_workers.sh's allocation requests. The host creates separate native containers, publishes receipts and proves exact container retirement. NativeAttemptFactory connects admitted Attempts to these ports. deployment/nmrnet-provider@.service keeps that host process alive; provider/deployment/install freezes inputs and installs its service profile. This is why replacing only systemd with a Docker restart option would be incomplete. Source N1.

The scientific connection is currently single-use. PredictionSession consumes one prepared handle; SelectedReleaseModels explicitly releases model/scaler references between heads. No current warm-model qualification is implied. The existing private protocol token correlates preparation and execution on a native connection; it is not the removed model-facing submit/token round trip. Source N2.

Two refinements to the preceding discussion are therefore necessary:

  • Fresh processes for every Job and retaining loaded models across Jobs are alternative inference lifetimes. The chosen end-state below reuses a healthy supervisor and container, but uses a fresh scientific child for every native operation. Neither inference-process nor model-cache reuse is required.
  • “Restart does not repeat a Job” does not prohibit the already admitted single replacement of pure prediction within the same Attempt. Preserve that narrow policy and its original causes; do not broaden it into whole-Job retry. Source N3.

Copy the donor supervisor's separation of lifecycle observation from scientific wire handling (source P1). The permanent supervisor runs a serial accept → fixed child spawn → wait/reap → scratch cleanup → retirement reply → accept-next loop. A normal operation does not restart the container: Docker restart/backoff is for abnormal container exit, not the ordinary throughput loop. Accepting a new operation does not retry an earlier one. Keep the lifetime lock held throughout the supervisor's lifetime and inherited by its one active child.

Separate lifecycle and scientific channels: one accepted control connection owns one operation. The supervisor creates a scientific socketpair, passes the child end and operation identity to the fixed native child, and sends the provider end as exactly one SCM_RIGHTS descriptor with its bounded startup greeting. The greeting identifies generation, admitted lock and operation. The child alone reads scientific requests and emits result/refusal frames. After the bounded retirement sequence, the supervisor sends the correlated lifecycle reply with the separate observed facts on the control channel. It never reads scientific payloads. A private prepared handle still authorizes only that operation's execution.

This separation is necessary: the current science framing is length-prefixed. If a child dies during a frame, appending retirement to that damaged stream cannot reliably establish its boundary. The control connection remains independently readable. This adapts P1's protocol-blind process ownership and S1's socketpair separation; descriptor transfer is new, explicitly qualified work, not an existing donor guarantee. Source N7.

Receive the descriptor with bounded recvmsg before any asyncio stream buffering can consume its ancillary-data byte. Admit exactly one AF_UNIX stream descriptor with close-on-exec reception; refuse ancillary truncation, unexpected control data and wrong descriptor types, closing every received descriptor on rejection. Transfer rights once even if greeting bytes need partial-write continuation. The supervisor closes scientific endpoint duplicates after spawn/transfer. The child inherits only its science descriptor and lifetime lease, never control/listener or provider-side endpoints. Interrupted socketpair/spawn/greeting/transfer setup remains owned and reaps any child before reporting completed cleanup. Primary API reference D2.

Observed scientific startup: the fresh child sends a binding-owned startup message on the science channel before preparation. Move the existing worker_main.py::_prediction_handler Python/distribution observations from its metadata file into that message. The client admits them into NativeAttemptFactory._prediction_runtime and the existing runtime_expectations before the current dependent Attempt setup/START boundary. The generic supervisor neither reads nor invents these facts. A replacement runtime mismatch still blocks prediction. Model/scaler byte verification and actual load observations remain at the release owner; startup does not load models to manufacture readiness. Startup failure retains its scientific cause and still requires independent lifecycle cleanup. Source N1.

Bounded control output: there is one bounded greeting and one bounded retirement reply, not an output queue. Use deadline-bounded socket writes within the remaining startup/cleanup budget, including partial-write continuation; no write may wait indefinitely for a connected reader. Failed startup delivery owns and reaps any child it created. Failed retirement delivery after known child/scratch cleanup closes control and reports the owned delivery failure through Docker logs; the supervisor may then accept another operation. The original client's obligation remains uncertain until its bounded recovery settles it. Message facts, successful receipt and client-side grant release are three different observations. Lost receipt does not undo supervisor-known cleanup or require holding the entire healthy runner. Qualify a non-reading owner without adding an output scheduler.

Lifecycle frame encoding/admission has one shared owner in provider-core; scientific frame semantics remain in the binding. The minimum shared API consists of the fixed-child session supervisor, greeting/retirement facts and their bounded client admission. No generic RPC dispatcher, arbitrary argv request or second molecular parser is needed. Two fresh operations and a failed/retired operation are the first installed package integration contracts.

Operation scratch: the supervisor owns one current operation directory under an explicitly bounded, container-private tmpfs and supplies it as the fixed child's working directory/TMPDIR. The lifetime-lock file is outside this tmpfs on its persistent private local mount. Source bytes enter through the scientific channel; no host source tree, credential, durable store or output archive is part of scratch. After child reaping, remove the owned directory without following links outside it, then acknowledge successful retirement and accept the next operation. All scratch cleanup consumes the same finite cleanup budget.

Scratch admission has distinct owners: the finite host deployment command admits the exact container's Docker tmpfs declaration, image and grants. A bind-backed directory fails that mount-kind admission even if private, empty or located on a host tmpfs. The shared supervisor owns safe use of the granted root: hold a no-follow directory descriptor, check owner/mode and require an empty operation root at startup. Its correlated greeting reports those local readiness facts alongside generation and lock identity, not an independent mount-type attestation. The trusted Engine preserves its admitted configuration across restart. A runtime mountinfo parser would duplicate the host's decision without proving old-mount destruction, so it is deliberately excluded. Source D3.

The binding consumes this supervisor observation and the qualified Engine/lifetime contract. It does not independently observe destruction of an earlier mount. After old lifetime holders have stopped and the successor's declared private tmpfs has been admitted, old scratch is no longer granted or reachable to supported native work. This is not a secure-erasure claim. The installed witness must leave scratch remnants, crash the supervisor, observe actual Docker restart and fresh-root admission, and separately prove the host refuses the wrong scratch mount. No host daemon, mount registry or path-name-only proof is added.

If scratch removal fails after reaping, report “child stopped; scratch cleanup unconfirmed” with its bounded owned cause. Preserve the successful reaping fact, hold the client's remaining grants and stop ordinary admission. The supervisor exits so Docker tears down the private tmpfs and restarts the container. A successor needs both qualified lifetime-lock acquisition and admission of the fresh scratch root in the exact declared tmpfs/runtime before treating old runner scratch as no longer granted or reachable to supported native work. Lock identity alone does not prove filesystem cleanup. No per-operation scratch manifest or crash-cleanup registry is introduced; the supervisor owns its current directory and container teardown owns crash remnants. Controller-side source and store grants still need their own owners' settlement.

Provider dies while the runner survives: the supervisor observes control-stream closure, stops and reaps the active child, settles its scratch, then releases that operation session and accepts another. The new provider cannot bypass this ordering by reconnecting. Failed retirement keeps that runner unavailable and the obligation retained; accepting a second owner is forbidden.

Runner/supervisor dies: the proposed replacement barrier extends P1's existing exclusive lifetime lock. Keep one private lock file per fixed runner role on a local filesystem. Normal start, stop, restart and replacement preserve the same file/inode; neither supervisor nor cleanup unlinks or replaces it. Admit the file through the donor's no-follow, owner/mode and descriptor checks. Pass the held lock descriptor into the fixed native child; both retain it until process exit and close descriptors rather than explicitly unlocking. A successor supervisor may publish its handshake only after acquiring that same exclusive lock. Primary lock-semantics reference D2.

Keep each role's lock and socket in secrets/deployments/<name>/runtime/<role>/, outside immutable bundles, temporary socket trees and container tmpfs. Install creates these private leaves and lock files once under the deployment command lock; later commands validate and preserve them. Mount only the role leaf into its runner read-write and the provider read-only, never the parent secrets directory. Use the admitted nonroot caller identity. Supervisors may replace their owned socket, not the lock inode. Ordinary install/up/down/restart never delete these leaves. Explicit decommission may remove them only after all exact owners and outstanding Engine effects have confirmed retirement; no routine garbage collector is needed.

The supervisor is the container init's main child, following the donor's init: true posture. Supervisor death must make init exit; container teardown kills the remaining namespace processes, and Docker then restarts the runner. The inherited lock blocks overlap during that teardown. The installed qualification must demonstrate this whole path with a blocked/TERM-ignoring native child, not merely show a successor waiting forever for its lock. No extra child parent-watcher, host monitor or provider engine grant is introduced.

The binding associates its active operation with the original owner session and admitted lock identity. A trusted successor handshake after exclusive acquisition of the same inode establishes that the previous protected process scope no longer holds its lifetime lease. Together with settlement of the binding's own I/O and confirmed runner-scratch release under the recovery contract above, that permits release of the old operation's grants. It does not supply a waitpid exit status, completed result or permission to retry. Missing/mismatched lock identity keeps the old obligation held. The core contract requires confirmed stopped work and released grants; it does not require inventing an OS exit code. Source N5.

Lost-control recovery owns its new session: obtaining that handshake also creates a fresh operation and scientific child. The existing factory must retain the entire connection/descriptor handoff as incomplete recovery setup before admission. Validate role, lock identity, supervisor generation and fresh operation identity. In the same supervisor generation, the serial loop accepts another operation only after reaping the previous child and cleaning its scratch. In a successor generation, exclusive acquisition of the same lifetime lock and fresh declared tmpfs/scratch-root admission supply that barrier. Neither path recovers an old result or authorizes scientific replay.

Send no prepare/execute or other scientific command to this proof session. Failed proof-session cleanup remains the factory's owned obligation and blocks replacement. Use the remaining cleanup budget, without resetting it or entering an unlimited reconnect loop. This adds no registry or second startup protocol. Test zero scientific commands and retained ownership when the proof child cannot retire.

This inherited-lock extension is proposed work, not a qualified donor feature. The current P1 lock is supervisor-owned. T1 must test supervisor death with a live TERM-ignoring child, refusal of takeover until child exit, the successful successor handshake, and refusal after lock replacement. The initial native contract is fixed single-process workers with library threads. Inspected NMRNet scientific/provider Python has no direct subprocess, multiprocessing or DataLoader launch, but that source observation does not establish the behavior of all installed native libraries. Qualify the supported installed runtime before accepting the contract. Existing scientific lifetimes: construct fresh SelectedReleaseModels, PredictionSession and ReleasedPredictionSession state in each native child. Keep the existing verify/load/release sequence for every head. Do not reset the old session's one-execution flag. New images or model selection require explicit deployment replacement, not mutation of a running session.

This is the complete intended end-state, not a temporary cold-worker mode. It removes host per-Job container creation/retirement and the permanent host monitor while keeping the native process lifetime close to the qualified implementation. The first draft required a one-head cache; the next proposed process/import reuse. Independent clarification exposed extra control and release semantics for those optimizations. They are not necessary to achieve the deployment goal.

Deferred optimization: process/import reuse or decoded-model caching requires a separately justified workload and measured benefit. A later proposal must specify quiescence, warning/artifact provenance and resource bounds. Repeated mixed H/C workloads would evict/reload a one-head cache anyway. This migration adds no reuse selector, dormant cache or warm-request protocol.

RDKit gets a new child for each parse/generation operation, including each correction attempt. Use bounded immutable bytes and fixed installed handlers; do not share a host source tree between Jobs. Scratch is private and bounded, and no new operation can use it until the previous child is reaped. A fresh child in a persistent container is not a fresh container or a hostile-code sandbox. Persistent runner isolation is an intentional change; document the common UID, filesystem grants and the supported untrusted-data threat model accurately.

Start-to-finish budgets include queue/readiness, parsing/generation, inference, any admitted replacement and result handling. Derive finite outer deployment/test waits from their owned inner budgets, with explicit cleanup grace. Do not reuse one arbitrary numeric bound for bytes, calls and seconds. No unlimited daemon-work timer is required; individual operations and shutdown remain bounded.

Both process streams go to Docker logs. For the portable end-state, use the sibling Compose json-file policy with explicit rotation (max-size: 10m, max-file: 3) per service, preserving mode: non-blocking and max-buffer-size: 1m from the current logging owner. Nonblocking delivery prevents log backpressure from stopping lifecycle progress, but drops new messages when that buffer is full. Durable outcomes and effect receipts retain their independent authority. Delivery semantics: source D1. Use this per-container policy rather than requiring host journald. Retain existing redaction, safe owned causes, request/Attempt correlation, primary-versus-cleanup distinctions and actual API acknowledgement facts. Do not restore application log dump files or generic exception stringification. Source M1; source N4.

Log rotation is a finite diagnostic window, not scientific preservation. Restart of the same container retains its log history within that window; removal/recreation can lose it. Stop preserves containers for inspection; explicit replacement/removal documents that consequence. Durable result/recovery records remain in their existing store and selected qualification evidence follows U19. There is no new log archive service. A healthcheck reports usable readiness; Docker restart is driven by process exit, not merely an unhealthy flag. Source D1.
