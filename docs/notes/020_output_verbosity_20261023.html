020 — Output verbosity and significant digits

23 October 2026. Implementation checkpoint: 2efc810 — Add shared output settings and scientific result verbosity. This record describes local source and contained qualification. It does not claim a new live model interpretation, provider announcement or API/GUI transaction.

Decision and rejected alternatives

The user requested selectable result detail alongside significant digits, using the established names low, medium and max. Proposed compact/full names and aliases were rejected. One shared output fragment contains both choices; defaults are medium verbosity and 4 significant digits. The small interpretation record stays at every level: it explains input selection without a transcript. Hiding it would save little while removing useful scientific provenance.

LevelScientific and supporting fields
lowEvery H/C prediction, full ordered atoms, source/record/member correspondence, generated-atom and H-parent mapping, generation provenance, conversion, coverage, model/runtime identities, interpretation record, warnings and limits.
mediumLow plus the prepared request and admitted float32 coordinate array.
maxMedium plus execution.tool_sources, the per-file software manifest.

Low does not preserve a self-contained geometry for supplied or generated input. A digest identifies bytes; it cannot recover them. There is no post-publication detail upgrade or promise to regenerate an identical geometry. Prepared decimal-to-binary64 coordinates and admitted float32 coordinates can differ, so medium retains both rather than calling either redundant.

Magnet provided vocabulary and presentation precedent, not NMRNet field policy: strict three-level enum, scientific offering description, and interpretation metadata retained across tiers. The offering copy was revised through independent chemistry-reader teach-back and source review. The catalogue summary links to the detailed scientific guide.

One fragment, existing owners

"output": {"verbosity": "medium", "shift_significant_digits": 4}

Core owns only the enum and exact string parser. NMRNet's immutable OutputSettings owns defaults, precision and JSON admission. Missing fields receive defaults; explicit null, booleans, unknown fields, aliases and invalid values are rejected. All three interpreter preparation tools use this parser before source acquisition or native allocation. Direct coordinate JSON uses the same object at its binding boundary.

The direct path strictly decodes the entire bounded input before separating output preferences. Duplicate keys cannot disappear during that separation. Original source identity covers the complete verified bytes, including output; scientific request identity covers the derived coordinate request. Native prediction still admits only atoms, coordinates and coordinate_unit. Configured production interpretation remains the deployment path; this does not introduce a public interpreter bypass.

Sources at the implementation checkpoint: core vocabulary, immutable settings, direct binding, preparation capabilities, strict decoder and unchanged native field admission.

Scientific admission, capacity and replay

Result schema v2 records the complete output choice. All scientific outcomes are validated before publication projection. Significant digits (1–17) affect published numeric values only; protected unrounded observations remain unchanged. Precision is not an accuracy claim, and JSON numbers do not preserve display trailing zeros.

The public reservation and final encoding use the same projection under the existing 786432-byte limit. Full prepared identity and scientific evidence remain subject to their existing 262144-byte ceilings. Native framing and resource limits are unchanged. A smaller public view never bypasses these independent gates. Existing terminal bodies retain their exact bytes and original schema during store reopen and lost-receipt replay.

Sources: _public_envelope, ResultPlan, rounding and admission; prepared identity and private evidence admission. The pure public-sizing test deliberately uses an oversized synthetic manifest; it is not evidence that this manifest could pass private persistence admission. A separate Session test refuses oversized private identity before worker work.
