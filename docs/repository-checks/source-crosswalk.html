Implemented proof and adaptation

  • test_proxy_posture.py: all 21 test_image_build_proxy.py methods and their injected sockets, monotonic clocks, DNS packet, privacy sentinel, request body, half-close, thread-capacity and atomic readiness cases. Production module path changes to the actual tools/bound_http_proxy.py; required absent primitives fail explicitly before a mock can contact DNS or a real socket. No network.
  • test_container_port_runtime.py: all eight runtime assertions. Identity is the launcher-injected NMRNET_EXPECTED_UID/GID, not a self-reported expected value. Current lane bounds are 512 MiB, two CPUs, 64 PIDs and zero swap. Actual mountinfo/status/cgroup/interfaces/filesystem are inspected. Build residue is observed only in this raw Python check image; this cannot certify inference image contents. Inference installation contents remain a separate image lane.
  • test_build_inputs_port.py: Dockerfile-specific deny-by-default contexts, exact COPY/ignore tool-leaf equality (including the source check whose original filename would not be discovered), known-good/bad parser cases, exact recursive upstream Python-file exception, ARG image pin binding, dirty authored source admission, immutable context retirement, offline build/import/device/secret grants, and second-output lock/advisory transaction failure. The original generated-source and package-lock tests retain no-write, hash, symlink and publication-durability proof; other dependency/source methods map to the dependency/source-closure ports, not duplicated weaker assertions here.
  • test_build_package_pinning_port.py: Dapp's PackagePinningTest and all parser helpers, exact regexes/options and uppercase assignment exemption. Apt and apt-get are BOTH admitted by this original source policy. No new same-layer cleanup or --no-install-recommends requirement is invented. Inventory extends to existing Dockerfile.lock; ignore files excluded; empty inventory fails.
  • test_operator_inputs_port.py: real current shell launchers with a finite fake engine. Explicit operator origins, literal GNU Make input (interface and archive), unknown/cardinality rejection, check nonmutation (inode/mtime/mode/ bytes), no automatic Git fetch, ambient engine/proxy/credential canaries, bounded-interruption statuses, exact returned CID admission, worker/proxy cleanup and retained ownership evidence on compound failure.
  • test_discovery_port.py: supported launcher selects actual Python discovery argv; the fake engine executes it in this already-contained process against an empty fixture. Zero tests must be status 2. Unknown fake engine commands fail 97, preserving Magnet's modeled-effect boundary.

The fake engine is an executable checked-in read-only fixture, symlinked into private noexec scratch. It never accesses a socket. Script interpreters resolve from the current contained Python executable. Git projection is finite and does not run Git. GNU Make itself must exist in the reviewed container; absence is an explicit failed proof prerequisite, never replaced by fake Make parsing.

Proxy and worker CIDs are deliberately distinct (c and d, each 64 hex digits). The double admits start/removal only for its own recorded identities; the cleanup assertion requires worker-ID removal before proxy-ID removal.

Native deadline/retirement fixtures retain engine doubles that close output while remaining alive, leave a descendant after leader failure, or let that descendant hold the output pipe. Before dispatch, the check requires a reviewed adapter binding an explicit short budget to an actual supported target deadline control. NMRNet currently has no such control/adapter: the proof prerequisite fails and these scenarios remain unexercised. The fixture's outer timeout only cleans up its own group; it cannot certify an operator deadline or impose a 0.5-second policy on an otherwise valid longer operation. Exact zero-budget dispatch, existing private-log collision and pipe-close injection refer to Magnet's run_native owner API, which has no equivalent configurable budget/log API here; those API-specific cases remain explicitly unported, rather than invent a new host-Python operation owner. Current discovered native probes also enforce private failure output, the original 8-MiB evidence cap and combined cancellation and cleanup truth. Exact systemd/BuilderCache/D-Bus cases remain S because their authority itself has no NMRNet consumer, unlike the unmet native-command obligations above.

Magnet permits only its exact recursive contexts.
