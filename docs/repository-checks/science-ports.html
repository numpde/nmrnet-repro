Headerless lock producer and independent index ownership

NMRPeak repository_checks/nmrpeak_lock.py:138-146 requires its own generated header to name the stage command and index: https://github.com/numpde/nmrpeak-repro/blob/f8055ab1065795fd46f8c1539e894cf9773f5495/repository_checks/nmrpeak_lock.py#L138-L146

The local producer deliberately invokes uv with --no-header, --no-emit-index-url and --no-emit-find-links. Requiring NMRPeak's representation would reject correctly generated local locks. The local parser therefore admits only headerless requirements and generated indented comments, rejecting top-level headers and resolver options. Index authority is checked independently: exactly one --index-url https://pypi.org/simple in inference.in, with no resolver option in build.in. Every pin, hash, ordering, continuation, byte-budget, direct-input and advisory-identity obligation remains enforced.

PackageLockStageTests executes today's actual producer with explicitly synthetic offline resolver and advisory ports. It checks the complete ordered uv invocation, exact emitted lock bytes and actual input/output report hashes. Its Torch fixture has one declared CPU wheel URL and one generated hash; normalization changes only the URL line to the matching CPU pin. The URL fragment and emitted hash must agree with the independently read declaration and CPython/Linux ABI. Only %2B versus + within the filename may vary. Additional, missing, mismatched or duplicated Torch/hash output fails before advisory calls or publication; no broad hash deduplication occurs. The strict parser separately rejects duplicate Torch hashes. Synthetic fixture text does not reconstruct or authenticate discarded historical uv output. Historical lock/report/image bytes and current operational adoption remain separate from this producer-contract qualification.
