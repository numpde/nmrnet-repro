RDKit dependencies and reader qualification

This reference records the dependency decisions and successive qualifications for the isolated RDKit worker. Early sections describe the evidence available when the candidate was selected; later sections record native-reader qualification. For supported inputs today, use the scientific guide.

preparation.in declares the separate RDKit closure for SMILES embedding and structure-file reading. It does not change inference.in, its lock, or the qualified prediction image. The existing package owner stages and applies this closure through make packages/preparation/lock/stage WLAN_INTERFACE=YOUR_INTERFACE and make packages/preparation/lock/apply STAGE=lock.ID. Review the complete preparation.lock and preparation-advisories.json pair before applying it. Application validates the selected input filenames and hashes as well as the lock hash; an inference report cannot authorize preparation outputs.

The preparation lock was staged and reviewed on 2026-10-18; its three wheels were downloaded and independently verified offline that day. No runtime was qualified at acquisition time. Lock staging records PyPI exact-version advisory metadata; that is not a complete native-code audit. An applied lock alone does not authorize exposing every RDKit reader to uploads.

MOL2 format authority and interpretation, checked 2026-10-19

Tripos, Tripos Mol2 File Format, SYBYL 7.1 (Mid-2005), original vendor manual hosted on a mirror:

  • p. 3, Glossary and Format Restrictions: section boundaries, comments, blank lines and backslash continuation.
  • p. 12, ATOM; p. 13, BOND: original atom IDs, XYZ and type fields; bond endpoint references.
  • pp. 53-54, SYBYL Atom Types: the complete concrete dotted vocabulary is C.{3,2,1,ar,cat}, N.{3,2,1,ar,am,pl3,4}, O.{3,2,co2,spc,t3p}, S.{3,2,O,O2}, P.3, H.{spc,t3p}, Cr.{th,oh} and Co.oh (braces abbreviate alternatives). LP, Du, Du.C, Any, Hal, Het and Hev do not identify one supplied nucleus. In particular, Du.C cannot become carbon; S.O denotes sulfur.
  • p. 8, ALT_TYPE describes separate alternate type sets; p. 51, UNITY_ATOM_ATTR includes charge, chirality and isotope attributes.

Printed and PDF page numbers coincide in this 54-page edition. This table supports the listed mappings, not a universal rule accepting any suffix after an element. Accepting further bare element spellings through the existing element authority would be our declared extension. Ignoring graph/alternate-type/attribute sections would be a declared coordinate-only projection, not complete molecular semantics. This evidence supports that design choice; it does not itself prove implementation, runtime behavior, scientific accuracy or RDKit compatibility.

Two explicit sulfur aliases have independent primary implementation evidence: MDAnalysis 2.9.0, SYBYL2SYMB maps both S.O/S.O2 and the commonly encountered S.o/S.o2 to sulfur; Open Babel 3.1.1, MOL2Format::ReadMolecule, lines 269-272 explicitly normalizes the two lowercase spellings to the uppercase forms. The manual's extracted text has uppercase O; a rendered page image was unavailable to the research tool, so no visual-verification claim is made. The independent tables agree with that reading. Accept these two exact aliases, not general case folding or arbitrary suffixes. The independent behavioral test covers all 27 documented dotted types and these two aliases. These sources support input interpretation, not a dependency on either library or runtime qualification.

SMILES generation evidence and design, checked 2026-10-19

The approved SMILES + conformer-count route is specified in note 003 and its tests-first sequence in note 016. Independent source review used the following primary RDKit references; these explain producer choices, not runtime proof:

  • Pinned SMILES parser parameters default to removing explicit H. Set removeHs=False before parsing so source H identity survives. Plain SMILES disables CX extensions and name parsing.
  • AddHs API returns a new molecule. Its pinned append loop and implicit-H branch preserve the original prefix and bond appended H to the source parent. Record that map explicitly; added H have no original source-atom index.
  • Embedding API defines ETKDGv3, actual returned conformer IDs, pruning, seeds and threads. The tagged embedding parameters and algorithm distinguish attempt and timeout controls. Record the named preset, explicit overrides, SDK parameter snapshot, runtime, actual coordinates and IDs, rather than treating a seed as portable identity. ETKDG includes distance-geometry optimization; this route adds no separate UFF/MMFF post-embedding minimization, energy ranking or population weighting.

Contained introspection of the existing pinned preparation image confirmed rdBase.rdkitVersion == "2026.09.1", EmbedParametersToJSON, timeout, maxIterations and the named ETKDGv3 preset. The preset exposes random seed -1 and timeout 0 by default; production generation must apply explicit admitted values. This inspection generated no coordinates and qualifies no input route.

The initial producer will return frozen generated requests and provenance, without forcing generated H or conformer IDs into supplied-file row/record fields. The existing batch/result owner remains authoritative when this value is bound to a Job. A shortfall retains actual IDs/coordinates privately and rejects the whole preparation, without reseeding or silently lowering the requested count. No disconnected-component exclusion was authorized in 003/016. Record actual generated positions without claiming an experimental relative pose for separate components; do not introduce a blanket molecular-equivalence gate here.

The pinned embedding implementation creates one timeout deadline at call entry, before fragment/conformer loops. This is a cooperative native-call deadline, not hard process termination. The wrapper description uses per-conformer/fragment wording; the tagged implementation controls this scope. The automatic attempt policy maps maxIterations=0 to ten times the embedded fragment's atom count. The producer requires an explicit positive attempt budget instead. Required settings are trusted composition inputs; no public tool may choose work budgets. The future worker binding must admit them against its fixed hard deadline before exposure.

EmbedParametersToJSON is a parameter serialization aid, not a promise to cover every effective choice. Retain explicit overrides and preset/runtime identity separately. GetFailureCounts returns aggregate counts for that embedding call, in the pinned EmbedFailureCauses enum order, not per-conformer reasons. A shortfall can include budget exhaustion; it is not classified as invalid molecular input.

Contained introspection of that same pinned serializer on 2026-10-19 showed property-tree string values: e.g. randomSeed="-1", timeout="0", numThreads="1", enforceChirality="true" and pruneRmsThresh="-1" for the untouched ETKDGv3 preset. The protocol compares any serialized explicit-setting fields against the admitted settings using that representation. Missing SDK fields stay missing; they are not invented from the request. This catches contradictory provenance without claiming that a self-reported snapshot proves native execution.

For each actual conformer ID, ROMol copy semantics allow retaining just that conformer with quickCopy=False, confId=id. AssignStereochemistryFrom3D then annotates atom/bond stereo from those generated coordinates. Its pinned implementation requires the 3D flag; replaceExistingTags=True invokes clearing/reassignment, avoiding stale CIP properties. Keep the original source atom/bond stereo separately and label the new annotations as generated-coordinate interpretations. RDKit-derived CIP labels are not experimental assignments or universal stereochemical validation. Source isotopes are retained even though the current model request schema carries only elements/coordinates; generated input has no enabled prediction route in this slice. Its later result/admission binding must preserve that distinction.
