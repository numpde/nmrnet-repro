Execution boundary
------------------
Use make test/repository. Python, behavioral shell probes, archive fixtures and
Git fixture operations execute inside its offline contained lane. Its grants
remain caller UID/GID, read-only root/public source inputs, no capabilities,
no-new-privileges, two CPUs, 512 MiB memory without swap, 64 PIDs, and a 64 MiB
noexec/nosuid/nodev scratch tmpfs. No engine socket or network is granted.

The host launcher records immediate root-entry types and names with find.
Checkers compare this independent inventory with the mounted public source
tree. A future public source path or cache that is not mounted fails visibly.
Private/control roots .git, .agents, .codex, .aws and acquisition/runtime .work
are classified without disclosing their contents. Only the temporary inventory
file is mounted from .work; the launcher removes it on exit, including failure.

The existing Python base image is reused without pulling or installing. Git,
GNU Make and Ruff 0.15.15 are missing contained prerequisites for some checks.
Scientific Git proofs also require a reviewed read-only Git object database
grant, which the current launcher deliberately does not provide. These failures
must not be interpreted as passing mutation proofs or repository violations.
Tool/image provisioning and Git metadata grants belong to the discussion.

Completed fixes and added regression checks
------------------------------------------
- Make unexports all seven raw selectors: ARCHIVE, STAGE, WLAN_INTERFACE,
  LABEL_ATOL, ATOL, RTOL and RUN_ID. Origin/value aliases preserve command-line
  inputs literally. ARCHIVE/STAGE shell consumers now use only their aliases;
  stage-apply guidance points to the maintained Make command. Unexporting also
  closes GNU Make's implicit export expansion of the already-admitted variables.
  Tolerance numeric validation still belongs to contained baseline_run.py;
  literal preservation does not claim pre-engine numeric validation.
- Release and Uni-Core source loaders reject unknown/missing declaration fields
  before acquisition. Their existing identity and publication semantics remain.
  Duplicate JSON fields, additional metadata value policies and receipt producer
  requirements were not silently claimed as repaired by exact-key validation.
- Proxy destinations require ports 1-65535; explicit HTTP port zero cannot select
  a scheme default. The 64 KiB limit counts header bytes through CRLFCRLF and
  preserves coalesced body bytes. Error diagnostics retain only phase and class.
  Forwarding is marked before its first write attempt, preventing a second HTTP
  status after uncertain writes or CONNECT setup. DNS/deadline/capacity/half-close
  and readiness refinements remain separate discussion items.
- Acquisition startup requires a full lowercase container ID agreeing with its
  regular nonsymlink CID receipt. Receipt comparison is byte-exact: 64 hex bytes,
  optionally one LF. Bash's NUL stripping cannot admit a malformed receipt.
  Interrupted creation can recover identity from its private owned receipt before
  stdout assignment; disagreement between nonempty identities cannot fall back.
  Cleanup refuses an unadmitted ID, retains uncertainty evidence, and retires and
  joins its owned attach client if a started worker's receipt becomes invalid.
- Removed only the observed untracked tools/__pycache__/package_lock.cpython-312.pyc
  and its empty parent. No acquired/model/result evidence was deleted.

Three new repository methods cover literal raw-selector export and actual

Independent review followed each small implementation bit. The CID byte and
