Execution boundary
------------------
Use make test/repository. Python, behavioral shell probes, archive fixtures and
Git fixture operations execute inside its offline contained lane. Its grants
remain caller UID/GID, read-only root/public source inputs, no capabilities,
no-new-privileges, two CPUs, 512 MiB memory without swap, 64 PIDs, and a 64 MiB
noexec/nosuid/nodev scratch tmpfs. No engine socket or network is granted.

The host launcher records immediate root-entry types and names with find.
Checkers compare this independent inventory with the mounted public source
tree. A future public source path or cache that is not mounted fails visibly.
Private/control roots .git, .agents, .codex, .aws and acquisition/runtime .work
are classified without disclosing their contents. Only the temporary inventory
file is mounted from .work; the launcher removes it on exit, including failure.

The existing Python base image is reused without pulling or installing. Git,
GNU Make and Ruff 0.15.15 are missing contained prerequisites for some checks.
Scientific Git proofs also require a reviewed read-only Git object database
grant, which the current launcher deliberately does not provide. These failures
must not be interpreted as passing mutation proofs or repository violations.
Tool/image provisioning and Git metadata grants belong to the discussion.
