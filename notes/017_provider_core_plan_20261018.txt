Local provider-core: reusable provider runtime, with U/A acceptance criteria
Date: 2026-10-18
Status: implementation authorized; installed Job-input slice qualified locally

Decision and scope
==================

The maintainer requests a local package named provider-core, intended eventually
to replace the corresponding provider infrastructure in sibling repositories.
The import namespace is provider_core. NMRNet is its first real consumer.
There is no dependency on magnet-provider-core and no request to modify Magnet.
The maintainer then explicitly required planning and U/A audit before building.
That planning step was documentation/read-only investigation. The maintainer has
subsequently authorized implementing the package tests-first; progress is below.

This decision supersedes 003's proposed shared-Magnet extension. It does not
cancel 003's three input routes, interpretation loop, scientific constraints,
container requirements or API/GUI end-to-end completion criteria. Sibling
migrations, external publication and deployment remain separate authorization.

Success is not a renamed fourth copy of a provider implementation. The installed
package must own the common behavior that the NMRNet workflow actually consumes,
with independently checked adoption contracts for Magnet, SECS and NMRPeak.
Their present implementations are evidence, not a universal behavioral template.

Finished ownership and enforceable invariants
============================================

1. API server owns authorization, eligibility, membership, expiry and committed
   Attempt state. Core authenticates exchanges and binds returned facts; it cannot
   create authority from text, a local flag, an interpreter decision or a receipt.
2. Core is the sole NMRNet owner of signing, bounded authenticated API transport,
   verified Job input, Job-bound Upload access, generic Attempt effects and exact
   terminal reconciliation. No second signer, downloader or replay owner in binding.
3. Binding owns scientific intent, typed interpretation tools, supported formats,
   geometry generation/conversion, scientific admission, model execution and result
   meaning. Core does not import NMRNet, RDKit, Torch, sibling packages or repo tools.
   XYZ and other chemistry readers do not move into provider-core.
4. Host/container composition owns actual network, filesystem, credential, resource
   and worker-retirement grants. Core consumes narrow execution/control ports and
   blocks new work when retirement is unconfirmed; it never receives an engine
   socket or implements a competing deployment manager.
5. Cross-module records distinguish original Job bytes, selected Upload bytes,
   prepared executable bytes and exact terminal bytes. Verified immutable bytes
   are the bytes consumed; paths do not become later unchecked authority.
6. One active Attempt per execution owner; NMRNet initially has one owner. Sibling
   composition may run multiple independent lanes with one shared claim authority
   excluding duplicate ownership and recovery races. Core adds no scheduler or
   process-global singleton. Determinate rejection, unavailable operation, potentially
   committed effect, observed committed effect, and failed cleanup are different
   states. No implicit queue, blind retry, science replay or generic catch-to-user-
   error conversion. Retry is an explicit bounded policy, not a diagnosis.
7. Errors carry the maximum safe useful cause, operation/phase, effect state and
   next action through the intended recipient's actual channel. Diagnostic-storage
   or cleanup failure cannot erase the primary cause or misreport commitment.
8. The package installs and executes independently of this checkout. Each adopted
   behavior has one owner and a real consumer. A sibling migration later replaces
   its analogue rather than wrapping old and new owners with silent fallback.

Package and composition
=======================

Proposed source layout: packages/provider-core/pyproject.toml and
packages/provider-core/src/provider_core/. This is a separately installable local
distribution, not a provider-named directory exported through root PYTHONPATH.
Keep public contracts small: verified source values, Job-scoped source access,
analysis outcome/effect values and an analysis processor boundary. Introduce a
port only where an actual integration or alternate implementation needs one.
No plugin registry, generic DAG, universal configuration language or event bus.

Layout workshop, 2026-10-18
--------------------------
The following is the intended layout as slices acquire real behavior, not an
instruction to generate empty files. The earlier conversational contracts.py
proposal is replaced by types beside their owning behavior. Public consumers
import documented owner modules; __init__.py stays small and has no startup effects.

packages/provider-core/
  pyproject.toml                 Distribution, build inputs and runtime dependencies.
  README.md                      Public API, ownership, containment and test guidance.
  src/provider_core/
    __init__.py
    job_input.py                 Verified Job instructions and their source identity.
    signing.py                   Signing inputs and authenticated request construction.
    transport.py                 Bounded exchanges, response consumption and retirement.
    api.py                       API wire operations and their explicit effect outcomes.
    uploads.py                   Job membership refresh/grants and verified consumption.
    analysis.py                  Preparation/execution boundary and outcome handoff.
    attempts.py                  Per-owner serial decisions and effect ordering.
    recovery.py                  Exact retained-terminal reconciliation policy.
    attempt_store.py             Durable records, atomic writes and retention capacity.
    diagnostics.py               Safe diagnostic context and recipient projections.
    container_guard.py           Shared execution-policy guard.
  tests/

    unit/adversarial/
    contract/

Types stay local: job_input owns verified instructions; analysis owns processor
outcomes; api owns wire/effect results; attempt_store owns persisted records.
Do not create a central types/contracts/utils bucket or mirror those definitions
in the NMRNet adapter. Extract a shared type only when it has one clear owner and
actual cross-module consumers. Errors likewise start beside their operation;
diagnostics preserves and projects their context, not a universal exception registry.

Dependencies point from orchestration to effects: attempts uses analysis, source
access, API operations and recovery; recovery uses the store and API reconciliation.
API operations use signing/transport. Upload access uses API membership/grants and
bounded store transport without forwarding provider credentials. The store does
not call the API or decide retry policy. Signing/transport do not import lifecycle
or science. Dependency cycles require correcting ownership, not deferred imports.

The consumer composition supplies the processor, policy, credentials and narrow
worker-control boundary. Its installed NMRNet binding imports provider_core; core
never imports nmrnet_provider. No generic executable/CLI, deployment manager or
plugin discovery is needed to make this library reusable. Host engine control and
actual filesystem/network/resource grants stay in repository composition.

The analysis boundary separates preparation from execution: binding returns an
admitted execution handle; core confirms required progress and durably records
execution entry before invoking that handle. Core cannot forge or reconstruct
session-owned handles. A monolithic callback that marks science entered before
interpretation/validation is insufficient. Binding owns generation compatibility
for pre-execution recovery. Terminal replay needs neither processor nor runner.
Execution-model decision, accepted by the maintainer on 2026-10-18: one async
provider orchestration implementation. The application composition owns the event
loop and task lifetimes. Core awaits API/store transport, interpreter/worker
protocols, readiness, progress, execution and recovery. Pure parsing, validation
and state decisions remain ordinary synchronous functions. RDKit and inference
remain synchronous inside isolated scientific workers, never on the control loop.

Rationale: cancellation, expiry and shutdown must remain observable while external
operations wait. Magnet already exposes awaited ports; SECS and NMRPeak need
explicit controller integration changes. Their synchronous owners may already use
threads; that does not establish compatibility with async cancellation or ownership.
P5 must qualify their async integration rather than merely matching data types.
No sync lifecycle twin, nested event loops, callable-result introspection or
automatic wrapping of arbitrary synchronous processors in threads.

P0 names the task owner, stop path and confirmation evidence for every blocking
effect. Inherently blocking durable storage may use a narrowly owned, serialized
I/O executor if needed; this is an explicit store implementation, not a general
sync-consumer adapter. Bound outstanding writes, preserve write order and await
their actual completion before dependent effects or store reuse. Cancelling an
await cannot cancel a filesystem write or prove that it failed. Storage failure
and uncertain persistence block unsafe advancement. No untracked fire-and-forget
task or thread may outlive its owning operation without retained recovery ownership.

Cancellation is a request to stop, not evidence that an API mutation, worker or
store operation stopped. Preserve each operation's effect certainty, execute bounded
cleanup under its named owner, and await required retirement confirmation before
reuse. Cleanup failure cannot replace the primary cause. Expiry/shutdown must not
be mapped to bad scientific input. Independent lanes may proceed only where their
claims/resources are independent; NMRNet initially admits one execution owner.
The outcome handoff also distinguishes successful result bytes from a binding-
classified failure projection and required protected evidence. Persist required
failure evidence before publishing its terminal report; storage failure blocks
that effect without hiding the primary cause. Product outcome vocabulary stays
in binding, including SECS cannot_analyse and no_starting_candidates.

One Job-scoped source owner refreshes authenticated membership observations,
invalidates stale acquired selections and acquires bytes through fresh grants.
Binding decides reinspection/reselection after an observed change; it does not
own a second downloader/cache. Freeze the identity of consumed bytes. The API
exposes no membership generation or atomic execution freeze: do not claim that
changes after the last membership observation are atomically excluded. P2 tests
removal after inspection, changed/unchanged membership after grant failure and
pending-hash finalization. Defensive same-reference metadata-change fixtures do
not establish that the server permits replacing finalized content.

Package metadata declares its actual runtime dependency requirements; the existing
repository acquisition owners maintain the separately reviewed exact core lock and
advisory evidence. Do not add a package-local build/download/test shell framework.
Installed tests must import the built distribution outside the checkout, with no
source-path injection. Tests, fakes, credentials, retained Attempts and scientific
artifacts are excluded from the runtime wheel. Required runtime resources are
explicit package data and checked in installed-closure tests; no resource directory
or duplicated schema/prompt is added without a real runtime consumer. In particular,
NMRNet interpretation prompts and geometry fixtures remain with the binding.

Evolution checks for this layout: replacing HTTP transport must not change Attempt
policy; replacing durable storage must preserve exact replay semantics; adding a
NMRNet format must not change core; changing an API field belongs at the wire
boundary and its consumers. These are ownership review questions, not an excuse
to implement multiple backends or a public interface for every internal function.

Concrete modules follow behavioral owners during implementation, not an up-front
empty module inventory. First useful behavior: verified Job text from exact
authenticated feed/response facts, consumed by the NMRNet submission adapter.
Then signed transport and complete Job-scoped Upload acquisition; then Attempt
lifecycle/publication and its required durable reconciliation. Packaging alone is
not completion. Do not ship an unused verifier as the finished shared package.

Configuration is admitted once per run: provider/API identity, destination trust,
Upload-store origin, deadlines/work limits and immutable implementation identity.
The caller supplies product policy explicitly. No NMRNet limits, absent-nucleus
semantics, solvent vocabulary or retry assumptions become core defaults.
Credentials never cross into the analysis/preparation worker. The scoped Upload
port takes an Upload reference; the interpreter cannot supply a different Job.

All development, building, installing and running remains contained. Core owns a
portable runtime guard rather than importing tools.container_guard; guarded entry
points reject unsupported host execution. The marker checks shared containment
policy; it is not proof of isolation or NMRNet-specific scientific policy.
Test real container grants and denial separately. Repository
tools/checks retain their current guards; new package sources enter guard, lint,
cache, source and build-context inventories explicitly, without blanket exemptions.
Use existing acquisition/build/test owners where applicable. Dependency acquisition
requires explicit interface selection; no ambient interface fallback. Independently
review current advisories for exact versions in the complete core dependency
closure before installing it. Keep it separate
from the qualified inference and preparation dependency locks.

The normative/adversarial split follows I:tests/unit/{normative,adversarial}/ and

Normative is not synonymous with happy path: required refusal, precedence and
atomicity are normative contracts too. Adversarial tests challenge those contracts
with tampering, substitutions, exhaustion and interrupted effects. Scenario tests
exercise complete meaningful stories (e.g. lost publication reply, restart, exact
reconciliation without another analysis). Integration tests focus on the actual
connections between owners, such as signed transport and store consumption.
Place each test under its primary purpose; do not duplicate it across categories.
Use normative/adversarial subgroups within other suites only where actual coverage
benefits. Adapter-specific tests belong with the boundary they qualify; S's adapters
directory does not require a new core adapter layer. Repo-checks, system/e2e and
model-behavior lanes stay separate from these package behavior categories.
Fixture data belongs beside its owning suite, with precise provenance for derived
examples. Within each layer, group by behavior; do not create empty directories.
Repository conventions and actual container/launcher grants remain repository-level
checks. NMRNet interpretation/model behavior and live API/GUI end-to-end tests stay
outside the shared package. Do not add model_behavior/live directories to core
merely to copy the sibling tree. Focused contained Make targets must preserve the
unit/contract/integration/scenarios distinction, allow focused normative/adversarial
selection, and select provider-core explicitly.

Concrete integration acceptance contracts
========================================

Retirement: composition confirms that the exact owned execution has stopped after
interruption, with the required grant cleanup. Successful quiescence and permitted
warm reuse are distinct from stopping a worker. SECS/Magnet retain successful warm
workers; a ready response is not evidence of stopping an interrupted execution.
NMRNet's initial container-retirement implementation confirms its allocated exact
container stopped and its grants were released. A shared name, timed-out wait or
stop request is insufficient. Core receives the bounded result, never an engine
handle. P0 names the controller, execution identity and actual confirmation scope;
P3 injects wrong/stale identity, supervisor loss and failed confirmation. Unsafe
work blocks reuse until confirmed stopped; successful warm reuse also requires
observed quiescence and completed per-Attempt cleanup under explicit consumer
policy. No general deployment interface is introduced.

Interpreter (NMRNet binding, not core policy): preserve original Job instructions
separately from admitted executable bytes. Test direct and interpreted routes,
bounded endpoint/repair calls and an overall deadline; malformed direct JSON must
not silently become prose. Distinguish model-reported input problems, deterministic
admission rejection, endpoint failure and indeterminate execution. Interpreter
egress uses an explicitly trusted destination and its own credential grant; source
or model output cannot widen Upload authority. Include credential/private-data
canaries and ensure rejection cannot start preparation. 003/016 own format,
conversion, native-work and result-size limits; these witnesses exercise them
through the real binding rather than duplicating scientific policy in core.
Following 014 W03/W04, test configured endpoint order and bounded fallback; explain
to operators and commissioners what request material goes to external interpreters.
Fallback must not override a terminal source-problem report. Test that such a
report ends interpretation without calling another endpoint or starting preparation;
operational fallback must preserve the stated deadline and effect-certainty rules.
Include wrong/ambiguous-unit fixtures through binding conversion, proving core
neither infers nor repairs units. Account failed and partial preparation work
against the same admitted work/time budget as successful preparation.

Recipient projections must use actual supported channels, grounded in I and G:
- Commissioner: terminal providerFailure.code/message, rendered by
  G:app/src/features/workspace/ColumnExecutionAttempt.tsx, carry safe useful cause
  and next action. In-progress providerCondition.code selects the GUI catalog's
  message/next_action, with observedAt; it cannot carry arbitrary per-Job detail.
  Do not turn uncertain delivery into a false terminal failure to get richer text.
- Receiver: the authorized result/download carries scientific limitations and
  provenance, including the existing scaler warning. Never invent a successful
  result for a failed or unresolved Attempt.
- Operator: protected recovery output preserves operation, causal chain, exact
  effect certainty and permissible retry/reconciliation action.
- Developer: protected diagnostic evidence retains safe causal detail and source
  identity needed to reproduce the failure, without raw credentials or input dumps.
P0 names concrete API wire fields, result renderer and protected diagnostic/recovery
store or sink for every supported path. P4 covers normal rejection, unavailable
service, uncertain delivery, cleanup failure and diagnostic-store failure on their
meaningful recipient paths. Assert safe cause, effect truth, retry disposition and
next action where applicable; secret canaries must stay absent. Storage/cleanup
failure remains secondary evidence and cannot erase the primary cause. Do not
invent a generic projection framework or a meaningless Cartesian test matrix.

Reuse evidence qualifies a design for adoption. Only an actual sibling cutover,
with qualification and removal of its old owner, proves shared production use.
