Routine logging and protected diagnostics
========================================

Intent
------
Use ordinary Python logging and Docker-backed bounded collection, following the
inspected Magnet serving practice. Do not add twig2, a collector container, a
cross-container queue, a stdout wrapper, or a second lifecycle authority.

Routine lifecycle messages go through a standard stdout StreamHandler. Owned
nmrnet_provider/nmrnet_inference loggers default to INFO; DEBUG is an explicit
host choice. Dependencies have a WARNING floor enforced at the handler as well
as the root default, including dependencies that enable their own INFO logger.
Only executable entrypoints configure logging; imports remain passive.

Private stderr is a different contract. Native failure notes can contain the
last copy of completed predictions after a failed result send, or RDKit messages
containing supplied molecular text. Controller stderr carries protected rendered
operator reports. Preserve those existing private, capped files and structured
reports; never copy them into routine journald messages. RDKit's scoped capture,
warning policy, resource snapshots and exact-container retirement stay unchanged.
Normal stdout no longer needs a permanent per-worker file. Finite startup
capture/metadata stdout remains a binary handoff protocol, not a log stream.

Collection plan
---------------
Use Docker journald for normal components/workers. json-file rotation alone
cannot meet post-removal retrieval because these containers are removed after
each use. A fixed nonblocking delivery buffer bounds pending delivery without
making journal availability the lifetime authority. Dropped/expired logs are
possible; structured result/failure/control receipts remain authoritative.
Inspect the selected logging posture with the existing launch posture owner.
Unsupported journald refuses the launch; there is no silent alternate driver.

Host journald owns shared disk/age limits and journal access. Do not modify host
settings. This host's existing auto-cleanup-limits.conf declares SystemMaxUse=300M,
SystemKeepFree=1G and MaxRetentionSec=14day. These are shared limits, not guaranteed
14-day retention or a per-Job quota. A credential-free isolated container probe
on 2026-10-22 UTC successfully emitted a fixed marker and journalctl retrieved it
after --rm. This proves driver/access/post-removal behavior, not future retention.
