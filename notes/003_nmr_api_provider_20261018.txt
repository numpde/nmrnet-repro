Purpose and completion
======================

Call this stage "Read supplied 3D structures or generate conformers
from SMILES." Read one pasted geometry or selected records from an uploaded
structure file, converting established units to angstroms. Generate estimated
coordinates with RDKit from a SMILES molecular description. Keep each supplied
atom linked to its original source record, and retain the generated coordinates
and settings for SMILES. Both paths use the existing NMRNet input checks before
prediction. The umbrella word
"preparation" alone does not tell readers which operation is involved.
Source review and context-isolated reader teach-backs distinguished these two
operations; a misleading suggestion of record selection within pasted input was
corrected. This is a terminology change, not new runtime qualification.

A commissioner selects the NMRNet offering and submits an analysis request. The
provider interprets it, reads supplied geometries or generates conformers from
SMILES, checks NMRNet's input requirements, and predicts atom-associated H/C shifts
for publication through the API. Developers, operators,
commissioners and receivers must receive useful safe causes when this fails.

003 closes when the agreed user workflow and failure/restart recovery work through
a real contained local API deployment and its actual GUI surfaces, with portable
evidence and operating instructions. Startup, scripted peers or existing scientific
tests alone cannot close it. Production activation is separate.

Commissioner-to-receiver workflow
=================================

1. Publish a truthful offering and let an authorized project select it.
   Choose an existing active analysis kind when its semantics fit; a different
   implementation does not automatically need a new kind. Freeze implementation,
   runner and result identities. Use a dedicated provider identity or publish its
   complete offering set: hello replaces that provider's snapshot (014 W05).

2. Admit the authenticated Job and interpret the commissioner's request.
   Preserve exact original text and identity. Direct structured coordinate JSON
   may bypass language interpretation through a declared deterministic route.
   Recognizable malformed structured input must not fall through to prose.

   Three routes are required: SMILES plus requested conformer count N; plain-text
   coordinates for one conformer; attached Uploads plus interpreter instructions.
   Uploaded records need not be checked for molecular equivalence. The detailed
   preparation contract below governs these routes. Demonstrate all three, with
   representative requests, scientific inputs and rejection guidance.

3. Produce a bounded collection of source-backed geometries through deterministic
   preparation, then one scientific request per geometry.
   For supplied geometry, extract/select explicit atoms, order, coordinates and
   unit. Prefer selecting an exact representation for parsing over language-model
   transcription of numbers. Prove correspondence to the source, not just schema
   validity. Missing or ambiguous data must produce useful guidance; the language
   model must not invent coordinates, units, atoms or chemical facts.

   SMILES preparation is required and separately qualified. Record conformer count,
   seed, hydrogen policy, source-to-model atom map and actual generated geometry.
   Do not describe it as supplied or experimental geometry. Names/resolvers and
   force-field optimization are outside this slice; no inferred extra services.

4. Execute the admitted coordinate bytes through unchanged predict_request and
   SelectedReleaseModels. Original Job identity and executed-input identity are
   distinct. Direct coordinate JSON retains its bytes; extracted/prepared input
   has a separately identified output, passed unchanged after admission.

   Preserve 002's 1-128 atoms, finite float32 coordinates, dictionary vocabulary,
   duplicate/extra-field rejection, paired artifacts and verified-byte decoding.
   Require exact angstrom even for no-H/C input (002 checks present heads only).
   Conversion to angstroms happens explicitly before admission, with source-unit
   evidence and recorded factor. No hidden scientific repair. Keep original indices; skip
   absent heads; no-H/C input retains explicitly described successful empty output.
   H then C run sequentially and release each head.

5. Publish a validated all-or-nothing result through the existing API owner.
   Preserve unit=ppm and atom_index/element/shift_ppm in each geometry's order. Check full
   eligible coverage, index/element agreement and finite output; no partial H
   success after C failure. Link Job and executed-input identities, atom convention,
   fixed model/runtime and preparation provenance once. Retain safe interpreter
   model/prompt/config identity with the outcome, without secrets or raw prose.
   Freeze envelope/size against API and actual GUI preview/download: recipients
   must see correspondence, units, provenance and limits. No new renderer is needed.
   Return a separate identified prediction per geometry, never an implicit average.
   Predictions are not measurements, simulated spectra or confidence estimates.

Evidence and ownership
----------------------

InterpretationSession owns inspection, selection and same-conversation correction;

- "Use all records in the attached conformers.sdf; report each separately."
- "Use frame 2 of the attached XYZ; its coordinates are in nm."
The final guide includes complete rights-cleared runnable inputs, actual outputs
and visible correction examples. No implicit default N or selection on ambiguity.

Keep four responsibilities explicit: source access owns authenticated bounded bytes;
format readers/generation own preparation; admission owns executable geometry;
the existing inference callable owns shifts. The interpreter chooses from declared
operations and sees bounded facts/errors. It cannot supply executable code, host
paths, arbitrary URLs, parsers or invented coordinates for uploaded structures.

The shared prepared value is a nonempty ordered collection of geometries. Each
entry has a stable geometry ID, ordered element symbols, coordinates in angstroms,
source identity (Job span or Upload digest and record/frame), source atom identities,
and preparation provenance. Optional bonds support diagnostics only. Do not require
a shared atom array, shared graph, cross-record alignment or molecular-equivalence
test. Each entry must satisfy 002 independently. Use named immutable records at
module boundaries; do not add a separate schema registry or proof-token hierarchy.
Freeze nested values or exact serialized bytes too; a frozen record around mutable
coordinate lists is insufficient. Caller mutation must not change admitted science.

The preparation owner serializes one exact request per geometry for existing
parse_request and dictionary admission; the provider adds the explicit angstrom
requirement even for empty H/C output. Preserve exact source and executed identities
separately. Avoid a second implementation of 002 validation in tools or schemas.

request bytes unchanged and wraps them as one prepared entry. Both cases then use
the same admission and execution path, not separate scientific implementations.
That shortcut requires coordinate_unit exactly "angstrom". Other units receive
explicit correction guidance; conversion belongs to the declared preparation routes,
which create distinct executed bytes and identities, never mutate the shortcut.

Routes and supported formats
----------------------------
SMILES + N: require a source-backed SMILES and positive integer N within configured
limits. Parse in contained RDKit, add explicit H before embedding, then generate
N conformers with a fixed recorded ETKDG configuration and seed. Freeze the actual
RDKit version/algorithm parameters during qualification, not an ambient default.
No force-field optimization or energy/population weighting in this slice. Record
generated atom order and which H were added. Unspecified stereochemistry is not
resolved as an asserted experimental fact: disclose RDKit's generated choice and
preserve input stereochemical specification. N requests successful conformers:
if fewer are generated, return a concrete shortfall to the interpreter; never
silently reduce N or repeatedly reseed until success. A changed N requires source
authorization. Bound embedding attempts and CPU time; requested count is not a
guarantee of distinct conformers, and the guide must say so.

Plain text: accept an element/X/Y/Z table or one XYZ block with explicit units or
an explicitly documented input convention. Interpreter identifies source span,
column order and unit evidence; deterministic code parses the numbers. Do not have
the model retype numeric arrays. Require exactly one geometry. Ambiguous columns,
unknown units or multiple geometries return actionable correction/request guidance.
The existing declared coordinate-JSON route remains a one-geometry shortcut with
the same admission; malformed declared JSON cannot fall through to interpretation.

Uploads: authenticated source references select exact immutable bytes, not host
paths. Instructions may select records or all records. Ambiguous selection requests
guidance rather than silently taking the first. Preserve original record/frame IDs,
including gaps after explicit selection. No molecular-equivalence check. Parse
every selected record before inference; a failed selected record fails preparation
with its identity and reason, never silently disappears from a successful batch.
Source access rejects Upload IDs outside this Job's authenticated grants regardless
of interpreter arguments. Bind inspected/selected record identities to the admitted
Upload digest; later fetching must not silently substitute changed source bytes.

Target acceptance catalogue (each row needs contained fixtures before advertising):
The offering advertises only the qualified allowlist and supported variants below,
never arbitrary structure formats by extension. All listed rows are 003 targets.
- XYZ: one block or a concatenated frame stream. Own strict frame splitting/counts;
  RDKit's single-block reader alone does not establish multi-frame support.
- MOL and SDF: single MOL or SDF record stream, V2000/V3000 variants qualified
  separately. Preserve supplied H and atom order; reject missing usable coordinates.
- PDB: explicit MODEL selection or all models; preserve serial/record mapping.
  Never silently merge alternate locations. Require an explicit supported alternate-
  location choice when present; reject unsupported ambiguity with precise guidance.
  Qualify element extraction and missing-H behavior rather than guessing from names.
- MOL2: supported RDKit atom-typing dialect only, with the limitation in the guide.
  Split multiple molecule records explicitly and qualify each selected record.
Do not promise generic archives, trajectories or every dialect by file extension.
Unrecognized formats report supported alternatives. Do not add an Open Babel or
other fallback dependency without a concrete unsupported-format requirement.

For uploaded/pasted geometries preserve supplied atoms and coordinates: disable
implicit H removal, reordering and coordinate generation. A missing-H or 2D drawing
does not authorize inventing geometry. Explain which H predictions cannot be made;
if generation is wanted, require the explicit SMILES generation route. Planarity
alone is not evidence of a 2D drawing. Reader sanitization/bond perception must not
silently change the scientific input; qualify actual reader settings and mapping.
Supplied geometry is predicted as supplied; neither its coordinates nor predicted
shifts independently verify stereochemical identity/configuration. State this in
the guide and result limits, alongside generated-geometry uncertainty.

Units and plausibility
-----------------------
Normalize using a small declared unit vocabulary (angstrom, nm, bohr), with aliases
handled explicitly. Source declarations or documented format conventions establish
units; contradictory evidence returns feedback. Record original unit, evidence,
conversion constant/reference and factor. Obtain precise unit references before
implementing constants. Apply conversion once from original coordinates; validate
finite float32 values after conversion. Never rescale an already converted candidate.

Bond-length plausibility is diagnostic, not proof of units or correct chemistry.
Use supplied bonds where available, marking any inferred bonds separately; no graph
is required for coordinate-only input. Report implicated record/atom pair, observed
distance and rule/reference. Do not silently optimize, change atoms or infer a unit
from the best-fitting length. Qualify a small documented set of diagnostic rules;
unknown bond types remain unchecked, not invalid. Existing CH3Cl/CH2Cl2 NIST tests
are regression evidence, not universal bond-length acceptance thresholds. Warnings
accompany admitted results unless an independently justified structural rule fails.

Conversation and effects
------------------------
Expose a small set of typed operations: inspect a source; prepare supplied geometry
with format/selection/units; generate from SMILES + N; report a source problem.
Conversion is a preparation option, not an arbitrary scale-factor tool. Return an
opaque prepared-input reference and summary on success, plus any diagnostics. The
interpreter selects that reference for submission; it cannot rewrite its contents.
Keep this reference local to the Attempt, not a new persistent object service.

State flow: authenticated source -> inspect/select -> deterministic preparation ->
admission -> retained execution identity -> sequential inference -> terminal result.
An expected parse/admission rejection returns structured location/cause/correction
feedback to the same conversation. The model may change source selection or options
only within the commissioner's instructions. Repeated failures consume the same
turn/time/work budget. No retry resets the budget or silently drops records.
Do not rerun successful embedding merely to validate/submit its reference.

Budget exhaustion reports the last useful failure and what remains unresolved.
Missing source data cannot be repaired by inventing it. Endpoint, storage, parser
crash, resource exhaustion and inference failures retain operational causes; only
expected input failures invite conversational correction. Errors, not secrets,
reach the appropriate API/GUI/operator surfaces. Do not claim model-authored source
problems are independently verified. Protect against instructions embedded in files.

Bound source bytes, selected and discovered records, atoms, generated conformers,
embedding attempts, parser work, model turns, prepared output and total wall time.
Publish concrete limits from measured fixtures before offering admission. Reject
over-limit work before expensive effects where possible; streaming consumption must
also enforce limits. Preparation is a contained worker with no external egress and
no engine socket. Host orchestration must terminate and confirm retirement of stuck
reader/embedding work, as for inference; cancelling a Python await is insufficient.
One active Attempt owns preparation and inference; no implicit parallel worker pool.
Apply the inference privilege profile to preparation: nonroot, read-only root and
exact input mounts, cap-drop ALL/no-new-privileges, no credentials/network/engine
socket, bounded private scratch and explicit measured CPU/memory/PID/no-swap limits.
Its host-owned retirement seam exists before runtime reader integration.
Qualify the installed worker's actual RDKit/native dependency closure and import
origins with no ambient workspace/system fallback. A changed reference version
blocks qualification until its version-matched fixtures are deliberately reviewed.
