Configured runtime assembly: implementation plan, 2026-10-20
==========================================================
Purpose: make the existing input interpreter, acquisition, native-worker session
and core Attempt lifecycle usable through one explicit production assembly.
Implement and test this assembly before a continuous service loop or deployment
controller. The accepted full-dependency package remains unchanged. This plan
does not authorize sibling/upstream edits, external model calls or deployment.

Current evidence: at 4621bd851700c2d0b3ef662781b07651488e1000, native
scientific-smiles uses actual generation, released prediction, signed local API,
durable entry, exact host retirement and lost-completion replay, but scripts the
chooser and assembles owners inside its test. Upload preparation has real source
acquisition/reader proof with recording prediction. No normal configuration
decoder, credential-artifact parser or production assembly exists. ProviderAPI
has no Hello operation; host tooling prestarts qualification allocations rather
than providing a production allocator. Do not promote these fixtures into a
scheduler, infer external authority, or call assembly proof a working service.

Responsibilities and construction order
---------------------------------------
1. provider_core.credential admits bytes of the API-issued
   nmr.provider.private_signing_credential.v1 document. Preserve its seven fields,
   profile vocabulary, Ed25519 public/private pairing and canonical encodings.
   Reuse existing reference validators. Return a small immutable credential with
   private key excluded from repr. No key generation, registration, file discovery
   or alternative seed/environment credential format belongs in this parser.
2. nmrnet_provider.config decodes one bounded closed TOML document. Group settings
   by existing owners: API/TLS; ordered interpreter endpoints; Upload store and
   budgets; preparation/generation budgets; lifecycle and stable recovery scope.
   Delegate values to SigningIdentity/ChatEndpointSpec, UploadLimits,
   GenerationSettings, StoreLimits and existing lifecycle admission. Do not copy
   their numeric or scientific validators. Accept explicit secret/CA inputs;
   use verified system roots or an explicit CA, never disable TLS verification.
   No ambient credentials/proxies, URL/model defaults, route selector, command
   imports, hot reload or configuration framework. Reject unknown keys without
   echoing their potentially private names/values. Startup file reads are bounded
   regular-file reads, with explicit ownership/mode/symlink rules for secrets.
3. nmrnet_provider.runtime assembles existing owners for one selected authenticated
   Job. Worker ports/factories and observed execution/model/runtime facts come
   from trusted host composition, not from Job text or interpreter arguments.
   Keep lifecycle API transport separate from source API/store and model I/O:
   JobUploads -> InputPreparation(InputInterpreter, allocators) -> NMRNetSession
   -> AttemptController. The interpreter chooses the route. No new start/execute/
   publish state machine, reference registry, transport or replay journal.
4. The outer caller owns retained storage and lifecycle API I/O. Inspect storage
   before requesting fresh allocation or dispatch; retained nonterminal
   obligations require explicit recovery or refusal, not automatic replay.
   A caller supplying preallocated ports retains their setup/refusal cleanup.
   The native fixtures prestart workers before storage admission and therefore
   cannot establish allocation-after-inventory ordering. Input facts must come
   from the outer caller's actual signed ProviderAPI.jobs read and explicit
   selection, not a TOML FeedInputFacts lookalike. Bound any pagination. Keep
   recovery generation stable across restarts;
   disposable native-allocation IDs are not persistent deployment generations.
   Construct JobUploads shortly before use because its total deadline starts
   at construction. Before controller adoption, construction failure leaves
   created resources explicitly caller-owned or retires them with all causes.
   After adoption, settle the controller before releasing its dependencies.
   Unconfirmed retirement retains ownership and blocks replacement; do not race
   an independent session.retire against controller settlement or close retained
   storage while its selected owner still needs it.

Interpreter, failure and recovery policy
========================================

Use the existing core interpreter seam if compatible, with a NMRNet capability.
Do not borrow G01 solvent or SECS spectrum semantics. Configure ordered endpoints,
bounded requests/repairs and an overall deadline. Fix and qualify budgets rather
than copying unrelated timings/counts. Bound actual response consumption and
trickle duration; complete interrupted I/O before connection reuse (014 W03/W08).

Repairs may fix format/source selection, not invent scientific content. Operational
endpoint/protocol failure may permit bounded fallback; a terminal model-reported
source problem must not be overruled by another endpoint. Attribute such a report
to its producer, distinct from verified input rejection, outage and inference failure.
Explain what request material reaches the configured interpreter (014 W04).

Before inference, repeat interpretation only under the declared Attempt policy;
retain the executed-coordinate digest and preparation/interpreter identity through
the selected Attempt recovery owner before dispatch. This identifies the submitted
candidate even if no terminal result becomes available; inability to retain this
identity blocks dispatch. Establish that seam in slice 1, not a second journal.
Once inference may have begun,
do not reinterpret/recompute to recover an unobserved outcome. Replay exact prepared
terminal bytes on publication retry. Persist intermediate input only for a concrete
recovery promise, using the existing owner, not a new sidecar journal (014 W02).

The core owns start/complete/fail uncertainty and exact Attempt reconciliation.
Never infer commit from transport success or timeout. Storage failure blocks unsafe
advancement. Expiry is server-owned and not renewed by progress. On confirmed expiry,
stop owned work, preserve evidence, and neither resend nor manufacture a replacement
Attempt. If completion committed before response loss, recover that success.
The GUI shows Expired without per-expiry recovery advice: offering/guide text must
explain this Attempt has no published result and direct users to resolve outstanding
work with the operator before deliberately creating another Job. Preserve other
Attempts' results; promise no automatic resubmission.

Errors, but not secrets, must maximally inform the actual recipient. Developers
need phase/cause/source evidence; operators need Attempt/service effect and recovery
actions in bounded protected diagnostics and inspection. Commissioners need safe
specific rejection/unavailable/unresolved/failure reasons through API/GUI. Receivers
need results with limits or honest status. Stderr alone is not an acceptance surface.
Freeze each surface's owner, authorization, safe fields, bounds and retention.

Preserve primary/secondary causes, effect state and visible truncation. Do not map
all ValueError to input error. Bounding an oversized reason must preserve ordinary
rejection through API/GUI. Exercise model reports, tool history, nested exceptions,
captured output and storage/cleanup failures with private sentinels. Retain the
known scaler-version warning in protected diagnostics and disclose its compatibility
limit appropriately; no silent dependency refresh or tolerance relaxation.

Stopped inspection is one recovery step, not resolution. Use authenticated API
reconciliation and the existing owner's closed-record archive operation, bound to
the exact Attempt/record and reason. Preserve original evidence; closure does not
prove delivery. Unavailable API/in-progress Attempt remains held. Document restart
after archival and confirmed worker retirement; never delete journals to clear a hold.
