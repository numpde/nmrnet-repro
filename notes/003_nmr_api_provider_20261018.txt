Purpose and completion
======================

A commissioner selects the NMRNet offering and submits an analysis request. The
provider interprets it, validates or prepares the scientific input, runs NMRNet,
and publishes atom-associated H/C shifts through the API. Developers, operators,
commissioners and receivers must receive useful safe causes when this fails.

003 closes when the agreed user workflow and failure/restart recovery work through
a real contained local API deployment and its actual GUI surfaces, with portable
evidence and operating instructions. Startup, scripted peers or existing scientific
tests alone cannot close it. Production activation is separate.

artifacts/prediction-cpu-float32.json, SHA-256

It qualifies CPU float32, the selected fold-0 pair, four fixtures, 137 outputs,
64 historical positions and real 128-atom capacity. It does not establish general
chemical accuracy, ensemble accuracy, inferred bonds or archive-wide unit provenance.

reviews checked constraints inside that scope without adequately challenging the
product workflow. Interpretation of supplied input and generation of missing
geometry are different responsibilities. An interpreter belongs in this offering;
geometry generation needs its own scientific qualification if the product needs it.

Commissioner-to-receiver workflow
=================================

1. Publish a truthful offering and let an authorized project select it.
   Choose an existing active analysis kind when its semantics fit; a different
   implementation does not automatically need a new kind. Freeze implementation,
   runner and result identities. Use a dedicated provider identity or publish its
   complete offering set: hello replaces that provider's snapshot (014 W05).

2. Admit the authenticated Job and interpret the commissioner's request.
   Preserve exact original text and identity. Direct structured coordinate JSON
   may bypass language interpretation through a declared deterministic route.
   Recognizable malformed structured input must not fall through to prose.

   Slice 1 must settle the input-product decision before calling the contract
   frozen: do intended users supply explicit geometry, or must this offering also
   accept SMILES and generate geometry? Decide source forms, including authorized
   attachments if needed. Demonstrate representative requests, scientific inputs
   and rejection guidance. Do not assume a coordinate-expert audience because
   002 accepts coordinates. This is an explicit product gate; independent package
   and operator groundwork can proceed while it is resolved.

3. Produce one source-backed scientific input through a deterministic owner.
   For supplied geometry, extract/select explicit atoms, order, coordinates and
   unit. Prefer selecting an exact representation for parsing over language-model
   transcription of numbers. Prove correspondence to the source, not just schema
   validity. Missing or ambiguous data must produce useful guidance; the language
   model must not invent coordinates, units, atoms or chemical facts.

   If SMILES support is selected, add an explicit scientific-preparation sub-slice
   before qualification: justify the contained method, conformer/seed/hydrogen/unit
   policy and source-to-model atom map. Retain actual generated geometry and its
   producer identity. Do not describe it as supplied or experimental geometry.
   Names, resolvers, uploads and optimization are supported only when deliberately
   selected and qualified, never inferred from the word interpreter.

4. Execute the admitted coordinate bytes through unchanged predict_request and
   SelectedReleaseModels. Original Job identity and executed-input identity are
   distinct. Direct coordinate JSON retains its bytes; extracted/prepared input
   has a separately identified output, passed unchanged after admission.

   Preserve 002's 1-128 atoms, finite float32 coordinates, dictionary vocabulary,
   duplicate/extra-field rejection, paired artifacts and verified-byte decoding.
   Require exact angstrom even for no-H/C input (002 checks present heads only).
   No hidden unit conversion or scientific repair. Keep original indices; skip
   absent heads; no-H/C input retains explicitly described successful empty output.
   H then C run sequentially and release each head.

5. Publish a validated all-or-nothing result through the existing API owner.
   Preserve unit=ppm and atom_index/element/shift_ppm in supplied order. Check full
   eligible coverage, index/element agreement and finite output; no partial H
   success after C failure. Link Job and executed-input identities, atom convention,
   fixed model/runtime and preparation provenance once. Retain safe interpreter
   model/prompt/config identity with the outcome, without secrets or raw prose.
   Freeze envelope/size against API and actual GUI preview/download: recipients
   must see correspondence, units, provenance and limits. No new renderer is needed.
   Predictions are not measurements, simulated spectra or confidence estimates.

Interpreter, failure and recovery policy
========================================

Use the existing core interpreter seam if compatible, with a NMRNet capability.
Do not borrow G01 solvent or SECS spectrum semantics. Configure ordered endpoints,
bounded requests/repairs and an overall deadline. Fix and qualify budgets rather
than copying unrelated timings/counts. Bound actual response consumption and
trickle duration; complete interrupted I/O before connection reuse (014 W03/W08).

Repairs may fix format/source selection, not invent scientific content. Operational
endpoint/protocol failure may permit bounded fallback; a terminal model-reported
source problem must not be overruled by another endpoint. Attribute such a report
to its producer, distinct from verified input rejection, outage and inference failure.
Explain what request material reaches the configured interpreter (014 W04).

Before inference, repeat interpretation only under the declared Attempt policy;
retain the executed-coordinate digest and preparation/interpreter identity through
the selected Attempt recovery owner before dispatch. This identifies the submitted
candidate even if no terminal result becomes available; inability to retain this
identity blocks dispatch. Establish that seam in slice 1, not a second journal.
Once inference may have begun,
do not reinterpret/recompute to recover an unobserved outcome. Replay exact prepared
terminal bytes on publication retry. Persist intermediate input only for a concrete
recovery promise, using the existing owner, not a new sidecar journal (014 W02).

The core owns start/complete/fail uncertainty and exact Attempt reconciliation.
Never infer commit from transport success or timeout. Storage failure blocks unsafe
advancement. Expiry is server-owned and not renewed by progress. On confirmed expiry,
stop owned work, preserve evidence, and neither resend nor manufacture a replacement
Attempt. If completion committed before response loss, recover that success.
The GUI shows Expired without per-expiry recovery advice: offering/guide text must
explain this Attempt has no published result and direct users to resolve outstanding
work with the operator before deliberately creating another Job. Preserve other
Attempts' results; promise no automatic resubmission.

Errors, but not secrets, must maximally inform the actual recipient. Developers
need phase/cause/source evidence; operators need Attempt/service effect and recovery
actions in bounded protected diagnostics and inspection. Commissioners need safe
specific rejection/unavailable/unresolved/failure reasons through API/GUI. Receivers
need results with limits or honest status. Stderr alone is not an acceptance surface.
Freeze each surface's owner, authorization, safe fields, bounds and retention.

Preserve primary/secondary causes, effect state and visible truncation. Do not map
all ValueError to input error. Bounding an oversized reason must preserve ordinary
rejection through API/GUI. Exercise model reports, tool history, nested exceptions,
captured output and storage/cleanup failures with private sentinels. Retain the
known scaler-version warning in protected diagnostics and disclose its compatibility
limit appropriately; no silent dependency refresh or tolerance relaxation.

Stopped inspection is one recovery step, not resolution. Use authenticated API
reconciliation and the existing owner's closed-record archive operation, bound to
the exact Attempt/record and reason. Preserve original evidence; closure does not
prove delivery. Unavailable API/in-progress Attempt remains held. Document restart
after archival and confirmed worker retirement; never delete journals to clear a hold.

Contained deployment and normal service
=======================================

All Python, package work, fixtures, tests and science run in containers. Host
shell/Make/Git orchestrate. Acquisition follows existing explicit-interface,
advisory-review and lock workflows; builds consume reviewed offline inputs. Lock
refresh reviews the whole package-set diff, not index freshness. No upstream or
sibling changes without prior discussion.
Deployment orchestration remains host shell. Python configuration, credential and
state validation runs in contained helpers with only its required mounts; the host
shell invokes admitted engine operations. SECS/NMRPeak host-Python deployment
controllers are workflow precedents, not an exception to this containment rule.

Named workflow: initialize private config/state; install API-issued signing artifact
and separate interpreter credentials; build admitted images; preview configuration;
start; status/logs; stop/restart. API authority owns registration/issuance. Provider
installation must not obtain API runtime secrets or silently replace identity.
Use disposable local qualification credentials (014 W06/W07).

Bind retained state to API origin/provider identity and exclude competing owners.
Keep admitted configuration stable for a run; record config/image identity and make
rotation/edits/redeployment explicit. Reuse suitable snapshot/locking mechanisms,
not every sibling confirmation scheme. Down removes only owned runtime resources;
configuration, artifacts and retained work survive. No blanket clean operation.

Provider grants cover API/interpreter, and source access only if required. Admit
per-destination TLS trust: normal roots or explicit private CA, never verification
bypass. External access requires an explicit host interface, enforced sole route
and direct-bypass-denial proof; the existing host-network acquisition proxy alone
is insufficient. Local API/GUI uses a named internal network with tested external-
egress denial. Live model calls use a separate explicit external grant.
For API, interpreter, runner and any admitted source exchanges, prove whole-operation
deadlines and byte/work bounds, including trickling or failed responses, plus
completed interruption and transport release before reuse. Per-read timeout alone
is insufficient; reuse the actual transport owner's mechanism (013 X04), including
M:magnet_provider/provider_http.py and runner_session.py where compatible. Slice 1
must prove the binding uses those owners and identify any missing behavior there.

Inference stays offline/read-only/nonroot, cap-drop ALL/no-new-privileges, 2 CPUs,
4 GiB/no swap, 64 PIDs and bounded scratch. Provider CPU/memory/PID/scratch/storage
also get measured bounds. Mount only needed sources/socket/state; no service engine
socket, home or whole workspace. Bound actual reads, including partial/failing
ones and source growth; preserve existing same-buffer artifact consumption.

One active inference; reject concurrent admission. Host orchestration owns startup
and retirement. Cancellation or uncertain in-flight execution retires the exact
runner container; confirm engine termination before replacement/new inference.
If confirmation fails, admission stays blocked. Name and prove the bounded host
control route early; helper death/socket loss alone is insufficient. Successful
requests and determinate rejections may reuse the runner.

Normal operation publishes complete hello periodically, discovers eligible work,
reports progress and recovers temporary outages under bounded policy. Configuration
rejection stays visible. Container health, accepted hello, API availability,
interpreter reachability and scientific readiness are different facts. Define
truthful readiness for sequential model loading, without forcing resident H/C heads.
Keep offering descriptions within 1,024 Unicode scalars: concise input/limits and
full copyable guide URL; complete rights-cleared examples live in the guide.
Test the delivered text, not just its template (014 W09/W12).

Implementation slices and acceptance
====================================

1. Agree the usable offering and prove reusable owners.
   Workshop representative requests and settle the input/preparation decision.
   Prove pinned core package/resources/API compatibility. Freeze identities,
   schemas/bounds, interpretation/recovery policy, recipient surfaces and readiness.
   Establish credential/deployment/TLS/network owners and the concrete retirement
   control route. Missing core seams require a scoped revision, not framework copying.
   Exit: usable user journey and executable contract/configuration gates, with no
   placeholder identity or unresolved scientific-input decision. Update stale README.

2. Implement interpretation and scientific input preparation.
   Direct and interpreted routes converge at deterministic admission. Prove source
   correspondence, exact executed bytes, units/order, missing/ambiguous-input guidance
   and malformed-JSON no-fallback. Qualify any chosen geometry-generation sub-slice.
   Exercise endpoint policy with scripted peers and rights-cleared fixtures.
   Structural/unit/size rejection precedes artifact reads; dictionary admission may
   read dictionary before checkpoint/scaler decoding. Provider tests stay Torch-free.

3. Deliver the normal contained transaction.
   Connect actual binding, private runner, result projection and named deployment.
   Prove config/state ownership, credential/trust admission and network grants.
   Run all four 002 fixtures through the new path, retaining producer/population
   gates, 137 outputs, 64 positions, loaded-state and verified-byte checks. Qualify
   real 128-atom capacity and process overhead. Demonstrate an interpreted request
   through actual API discovery/selection, authorized submission, execution,
   completion and receiver GUI/readback. Exit: full normal workflow, not just mocks.

4. Close failures, restart and operator recovery.
   Exercise input/model-reported rejection, interpreter outage/repair/fallback,
   C failure after H success, artifacts, cancellation, malformed/lost runner replies,
   start/terminal response loss, expiry, storage/cleanup and hello/discovery outages.
   Prove exact outcome replay, no blind science rerun, replacement readiness and
   no orphaned work; inspect each recipient's safe diagnostic surface. Qualify
   stopped inspection/archive/restart. Add focused cases at actual owners, not
   an unrelated generic fault framework.

5. Qualify and hand off the complete offering.
   Repeat normal/failure API/GUI paths with final admitted images. Separately qualify
   the selected real interpreter endpoint/model with source-backed fixtures and
   semantic review of model-authored reports; scripted peers do not prove this.
   Routine bounded tests, costly scientific/capacity checks and external model calls
   use separate named hierarchical lanes. Credentials, disclosure and any paid use
   are explicit invocation prerequisites, not permission granted by this plan.
   Retain compact evidence: exact input/result populations, source/runtime/model/
   prompt/config identities and raw numerical observations. Where distribution is
   restricted, preserve hashes, access and rerun requirements. Document commands,
   trust/credentials, retention/recovery and usable examples. New Make selectors
   retain protected literal captures/unexported public inputs and extend the existing
   regression. Exit: fresh contained rerun and applicable current checks pass;
   distinguish implementation, local qualification and production deployment.

Retention follows purpose: offline inputs while needed; reviewed evidence while
claims remain published; debug captures/helpers until resolution or accepted
replacement. Check unique evidence/rationale/active work before cleanup. Attempt
retention must not erase the only published-claim evidence. CI remains deferred.
No new public prediction CLI, training, ensemble/GPU work or upstream edits enter
implicitly. SMILES preparation is the explicit first-slice decision, neither
silently promised nor silently deferred beyond the slice.
