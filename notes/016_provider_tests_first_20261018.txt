Tests-first working method
==========================

For each small slice:
1. Write a short behavior example and the relevant failure/forbidden-effect test
   at the owner boundary. Reuse existing fixtures where their provenance fits.
2. Run that focused test in the repository-owned container. Verify it fails for
   the missing behavior, not an environment/import/fixture accident. Do not run
   an entire science suite to establish a parser's initial failure.
3. Implement the smallest coherent owner. Run the same focused test group; then
   only affected integration/repository checks. Preserve independent expected
   observations, not values recomputed by the function under test.
4. Review the diff for important U/A and ordinary correctness/maintainability;
   fix actionable findings and repeat focused checks. Keep auditors available
   between slices. Apply 003's unchanged-round review discipline.
5. Commit a coherent passing slice using explicit -- FILE paths. Report tests
   actually run, remaining qualification and whether any public route is enabled.

Tests must establish externally meaningful outcomes: exact source mapping, no
unauthorized read, no expensive work after rejection, correct cause at the actual
recipient, no duplicate execution, no partial-success lie. Avoid asserting helper
names, dataclass layout, prompt wording or every private call sequence. Small
recording fakes are useful for effects; they cannot establish RDKit semantics,
engine retirement, NMR numerical behavior or actual API/GUI delivery.

Add focused tests immediately before each implementation, not a giant failing test
suite before any work. Disabled/unadvertised incomplete routes can land with green
internal tests; existing routes must remain usable. Do not expose a route until
its preparation, admission, execution and failure projection are integrated.

Module boundaries (proposed names, not a new framework)
======================================================

Use a thin nmrnet_provider binding to the proven packaged core. Suggested files
below may follow package-native naming after slice 1; responsibilities must remain.

input_contract.py: named route choices and prepared geometry collection. Pure,
lightweight records hold bounded identity, immutable data and private-safe repr.
It does not fetch files, import Torch/RDKit, validate model weights or execute tools.

source_access.py: authenticated Job/Upload access, byte/work budgets and immutable
source identity. Reuse the core's admitted source mechanism where available; do
not create a second downloader. A source handle is scoped to one Attempt and grant.

preparation worker: separate contained executable/module, not a general subprocess
service. geometry_readers.py owns deterministic parsing/record selection and calls
format-specific functions; split into reader modules only when format logic warrants
it. smiles_geometry.py owns RDKit generation. coordinate_units.py owns the small
conversion table and reference-backed constants. geometry_diagnostics.py owns
optional-bond advisory checks. These do not call the interpreter or publish results.
Only the worker imports RDKit. Source access resolves authenticated references to
bounded immutable bytes before worker dispatch. Host orchestration passes those
exact bytes through bounded stdin or an exact read-only staged mount, with record
selection/options and provenance. The worker cannot fetch Upload IDs or resolve
network references; no arbitrary code, host path or caller-selected executable.

geometry_admission.py: adapts prepared entries to existing parse_request and
dictionary admission, adds provider-wide angstrom/batch gates and serializes exact
requests. It does not copy atom vocabulary, float32 or model compatibility rules.
Direct angstrom JSON retains exact original bytes. Preparation routes create new
bytes. Keep source identity, executed identity and source atom mapping distinct.

input_interpreter.py: binds the supported operations to the existing conversation
owner, returns reader/admission feedback, and selects a prepared reference. It
owns no geometry math, file parser or unbounded retry loop. Its records do not
expose private source contents in repr or generic diagnostics.

batch_execution.py and result.py: thin sequential composition of the existing
runner and result publication owners. All entries admitted before checkpoint load;
one identified result per geometry, full eligible atom coverage, all-or-nothing
publication. No new scheduler, durable queue, journal or partial-result protocol.
Core owns Attempt lifecycle/terminal replay. The binding owns scientific projection.

Host shell/Make owns preparation/inference container start and confirmed retirement.
All Python/config checks/tests run contained. No engine socket in either worker or
provider. Preparation gets only exact inputs and bounded scratch, never credentials.

Implementation/test sequence
============================

0. Establish package/configuration seam before extending science.
   First tests: installed binding/resources resolve from admitted package; provider
   can import with Torch and RDKit unavailable; invalid configuration launches no
   work. Prove existing core lifecycle/transport owners are actually called.
   Freeze API result schema/size, grant access and measured-limit configuration.
   Missing required limits/qualified readers block offering admission in code.

1. Preparation boundary and direct/text routes (003 2a).
   First tests: source bytes/atom order survive; exact angstrom JSON is unchanged;
   non-angstrom shortcut rejects with useful guidance; text nm conversion yields
   independent expected distances; multiple pasted geometries reject; malformed
   declared JSON never invokes the interpreter. No checkpoint/scaler loads occur.
   Worker tests: timeout/crash leaves a truthful cause, host confirms exact worker
   termination, failure to confirm blocks new work. Prove hardening/mount/network
   profile with the actual contained launcher, not only a command-list mock.

2. Upload source ownership and XYZ/MOL/SDF (003 2b).
   Prerequisite before real-reader tests: review the full RDKit/native lock and
   current advisories, acquire through the explicit-interface lane, and build the
   admitted offline worker image. SMILES reuses this image later; dependencies
   cannot first be admitted in step 4. No installation occurs on the host.
   First tests: a model-selected foreign Upload ID cannot be read; changed bytes
   after inspection fail identity admission; failing/partial reads consume budget;
   selected record 2 keeps its original identity; bad later selected record prevents
   all inference. Explicitly selected good records can be used without parsing an
   unrelated record as though it were selected, while discovery still stays bounded.
   Reader fixtures include V2000/V3000, explicit H, same/different molecules, repeated
   frames, truncation and record count limits. Different molecules MUST NOT fail
   merely for differing identities. Prove all declared variants with real RDKit.

3. PDB/MOL2 variants (003 2c).
   First tests: model/alternate-location selection preserves source atom mapping;
   ambiguous alternatives fail explicitly; dialect failures name supported input;
   multiple MOL2 records cannot silently collapse to the first. Missing H never
   silently adds coordinates. Nonzero elements/atom inventory survive sanitization
   choices. Real reader fixtures, not mocked Mol objects, establish these facts.

4. SMILES + N (003 2d).
   First tests: N absent/noninteger/out-of-range fails before generation; explicit
   and implicit H yield documented generated mappings; supplied stereo survives;
   unspecified stereo is disclosed; fewer conformers than requested returns exact
   shortfall; retry/submission cannot reseed or regenerate a successful candidate.
   Unit tests inject shortfall/failure; real pinned RDKit proves generation and
   recorded settings/geometry. A seed is provenance, not a cross-version identity
   guarantee. No reference fixture matches the version => qualification fails.

5. Interpreter repair loop (003 2e).
   First tests: scripted tool replies inspect/select/prepare/admit one actual source;
   parser rejection returns record/field/cause; correction succeeds within the same
   total budget; a wrong prepared reference cannot execute; file instructions cannot
   alter allowed operations/grants. Candidate failures, model source reports,
   endpoint outage and worker crash reach different truthful outcomes.
   Repaired parsing/conversion may not alter the commissioner's molecule/N/selection
   intent. The unchanged prepared reference reaches execution without another parse
   of model-authored numeric arrays. Live-model qualification remains opt-in.

6. Advisory diagnostics and batch/result integration (003 2f).
   First tests: known implausible supplied bond produces a warning with record/atoms
   and scientific reference; graph-free geometry remains executable; warning cannot
   change coordinates/units. Independently known unit factors yield expected values.
   Batch tests: later admission failure loads no checkpoints; later prediction
   failure publishes no partial success; collection order/atom coverage is exact;
   repeated terminal publication uses identical bytes without a second inference.
   Result contains reproducible prepared geometries/settings and safe warnings;
   result size over limit prevents dispatch, not post-compute silent truncation.

7. Real integration and failure recovery (003 3-5).
   Preserve four-fixture/137-output/64-position 002 qualification and real 128-atom
   capacity. Exercise all three routes and N > 1 through real local API and GUI.
   Verify complete numeric download, source mapping, reproduction fields and warnings.
   Inject response loss/expiry/storage/cleanup failures at actual owners. Confirm
   recovery reconciles one Attempt; no rerun of earlier geometries after uncertainty.
   Check commissioner/receiver rendering and authorized operator inspection, not
   stderr alone. Explicit real-interpreter runs establish model behavior separately.

Hierarchical lanes and qualification limits
==========================================

Extend existing test/unit, test/repository, test/unit/prediction-input and
test/unit/bond-distances lanes; preserve prediction/tensor-parity,
prediction/model-parity and prediction/qualify for existing scientific witnesses.
Proposed new hierarchical targets: test/unit/provider, test/preparation/readers,
test/preparation/generation, test/provider/lifecycle, test/provider/api-gui and
interpreter/model-behavior. Names become concrete when their contained runner is
implemented; test/unit/provider now exists for the internal input foundation,
while the other proposed targets remain unimplemented. Do not replace
the harness or place costly/live lanes under default test.
Ordinary tests do not acquire artifacts or contact paid/external endpoints. Scripts
carry the shared in-container guard and repository checks enforce it. Existing
literal selector capture tests extend to any new Make inputs.

Slice 1 must freeze numerical upper limits with worst-case serialized result sizes
and measured preparation costs. Test exact limit and limit+1, as well as a failing
read/retry that consumes budget. Keep metadata/reader tests cheap; separate real
RDKit execution, model capacity and external-model calls. No blanket benchmark or
new performance campaign is required. CI remains deferred.
