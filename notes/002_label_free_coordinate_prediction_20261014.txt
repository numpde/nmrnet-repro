Label-free tensor composition
-----------------------------

`nmrnet_inference/model.py` composes the five CPU tensors for one admitted
ordered atom list and one H or C head. It uses only atom tokens, the element
selection mask, centered coordinates, pairwise distances, edge types, and
right-padding. Requests above 128 atoms are rejected before scientific imports
or pairwise allocation; the adapter does not apply the training dataset's
random crop. Exact dictionary identity/order and coordinate-unit qualification
remain separate gates. The same real-atom selection produces the `select_atom`
tensor and `selected_atom_indices`, a tuple of zero-based input positions in
model-row order. BOS, EOS and padding are excluded, and the mapping stays outside
the five model keyword arguments.

The operation order follows the pinned sources. `CroppingDataset` casts selected
coordinates to float32 (`NMRNetplusplus/uninmr/data/cropping_dataset.py:27-38`),
then `NormalizeDataset` subtracts their per-axis mean and retains float32
(`NMRNetplusplus/uninmr/data/normalize_dataset.py:20-26`). `UniNMRTask` orders
cropping before normalization, creates tokens and element masks, computes
Euclidean distances, adds BOS/EOS borders, and builds edge types
(`NMRNetplusplus/uninmr/tasks/uninmr.py:348-379`). `DistanceDataset` uses the
SciPy p=2 distance matrix and casts it to float32
(`NMRNetplusplus/uninmr/data/distance_dataset.py:13-24`). The task's right-pad
collaters pad each tensor axis to a multiple of eight
(`NMRNetplusplus/uninmr/data/pad_dataset.py:13-47,49-66,88-102`).

The coordinate boundary markers are scalar `0.0` arguments in the upstream
task. Uni-Core's pinned `PrependTokenDataset` and `AppendTokenDataset` create
each marker with `torch.full_like(item[0], token)`, so a scalar marker has the
same three-value row shape as the coordinates
(`https://github.com/dptech-corp/Uni-Core/blob/ace6fae1c8479a9751f2bb1e1d6e4047427bc134/unicore/data/prepend_token_dataset.py#L14-L25`,
`https://github.com/dptech-corp/Uni-Core/blob/ace6fae1c8479a9751f2bb1e1d6e4047427bc134/unicore/data/append_token_dataset.py#L14-L24`). The source pin and archive hash are recorded in
`requirements/unicore-source.json`: commit
`ace6fae1c8479a9751f2bb1e1d6e4047427bc134`, archive SHA-256
`ae240ff27dfc4c698081260d58ce4bee30d4f437fef23bed89d4033625f21583`.
`tests/test_prediction_model.py` uses these
actual wrappers as its oracle and checks exact tensor dtype, shape, and values
for H and C at one and 128 atoms. Its 128-atom fixture uses fractional
coordinates to exercise the float32-before-centering order. It also checks
CPU placement, zero BOS/EOS borders, eight-wide padding, malformed coordinates,
the pre-import and pre-distance 128-atom bound, oversized integers, and
non-echoing unsupported-atom errors. It verifies that selected input indices
match the real rows of the mask for repeated mixed H/C atoms, and that absent
elements have no selected indices or real mask rows. Unsupported-atom errors
report an atom index rather than repeating caller input, retaining an actionable
location without echoing the request payload.

Purpose and completion boundary
===============================

Implement direct H/C chemical-shift prediction from an explicit ordered atom
list and matching coordinates. A contained one-shot command must predict every
H/C atom supplied, preserve original atom indices, and qualify its computation
against the CPUfloat32 fold-0 reference established in note 001. Training labels,
label masks, LMDB records and loss evaluation must not enter the production
prediction interface. The existing model already accepts label-free tensors;
this slice removes the surrounding benchmark-data dependency.

Keep the same image/dependencies, dictionary, paired scalers and fold-0 checkpoints;
no new downloads/installations are expected. artifacts/reference-cpu-float32.json
and its original receipts remain historical evidence, not runtime configuration.

Explicitly defer SMILES parsing, hydrogen addition, conformer generation,
solvent-aware variants, five-fold ensembles, larger tensor batches, GPU/reduced
precision, persistent workers and NMR API integration. Ensemble prediction can
build on this adapter without waiting for SMILES support. Published Table 2
ensemble accuracy is not a claim of this slice.

Proposed minimal file ownership
===============================

- nmrnet_inference/model.py: the loaded scientific boundary and exact label-free
  tensor preparation, using upstream classes/helpers wherever available.
- nmrnet_inference/predict.py: bounded single-molecule JSON input, atom ordering,
  prediction, and ownership of the one-shot result and completion publication. No
  provider protocol, schema registry or version framework.
- tools/predict.sh plus one Make target: host orchestration and explicit container
  authority only, following tools/baseline.sh. No host Python.
- tests/test_prediction_input.py: lightweight offline admission/publication tests
  in the ordinary maintained test image; do not add Torch to that image. A fresh
  contained process must import the lightweight admission path with Torch and
  Uni-Core unavailable, and reject malformed JSON, field, shape, count and raw
  number inputs. Test that all input admission completes before checkpoint/scaler
  deserialization, model construction or forward execution. Dictionary-dependent
  vocabulary checks use the admitted dictionary before checkpoint loading. Keep
  heavy imports behind the lightweight checks; do not add an import framework.
  This applies 013 U11's dependency-boundary and forbidden-effects guidance; see
  its cited source and rationale at
  https://github.com/numpde/nmrnet-repro/blob/e6a8a1b1a2dd5cb854d70277f40d3275945ce933/notes/013_sibling_practices_20261016.txt#L151-L160.
- tools/prediction_parity.py plus a maintained qualification target: scientific
  tensor/checkpoint/prediction proof in the admitted inference image, against the
  verified original records and the 001 reference. Test data and original labels
  stay here, outside the prediction interface.

Consolidate filenames if fewer natural owners suffice. No generic adapter framework,
registry, configurable backend factory or mirrored model architecture is needed.

No fork change is currently justified. If an upstream helper needs extraction,
propose the smallest fork change, prove equivalence and update the submodule;
do not patch image-owned scientific source silently.

Operator contract
=================

Proposed maintained commands after implementation:

  make prediction/run INPUT=/path/to/request.json RUN_ID=coordinate-001
  make prediction/parity RUN_ID=coordinate-parity-001

The shared Make input guard recorded in 013 U12 is now in place: existing
launcher variables use protected literal captures, and `INPUT` is already
unexported. When adding the prediction target, give its launcher a new
command-line-only input variable using the same `$(value ...)` and `override
export` pattern. Extend the contained real-Make regression to prove that a
literal JSON path reaches that variable and that shell-bearing public and
launcher-variable values are never evaluated by Make. The shared guard passed
`make test/repository` with 480 tests in checker image
`sha256:9164d380c00bf0e013d44357cafb03d4b1f64570a93105f74ac4b85b66cf1b49`.
Implementation: https://github.com/numpde/nmrnet-repro/blob/80f6b92f13927a392296aead6be312a3e7d6ff7a/Makefile#L17-L25
and https://github.com/numpde/nmrnet-repro/blob/80f6b92f13927a392296aead6be312a3e7d6ff7a/repository_checks/test_operator_inputs_port.py#L127-L164.
Rationale and complete test result: https://github.com/numpde/nmrnet-repro/blob/5a892af9b7e8b6658e3c424e76d3c645fc3f23be/notes/013_sibling_practices_20261016.txt#L168-L195.

INPUT and RUN_ID are explicit command-line choices. Mount one regular input file
read-only at a fixed path; refuse symlink substitution. Fresh destinations are
.work/predictions/<RUN_ID>/ and .work/prediction-parity/<RUN_ID>/ respectively;
retain receipts/results/failures there without overwriting 001 evidence. The
operator does not choose checkpoints, device, precision, masks or model settings.

This is a local command format, not an NMR API input/result schema. One file
contains one molecule, with coordinate_unit, atoms and coordinates. For example:

  {"coordinate_unit":"angstrom","atoms":["C","H"],
   "coordinates":[[0.0,0.0,0.0],[1.09,0.0,0.0]]}

This illustrates shape, not a qualified sample. The unit spelling is provisional
until the gate below closes; no automatic unit conversion. Caller atom inventory
and order are authoritative: no addition/removal/reordering, canonicalization,
coordinate generation or repairs. These fields do not establish bond/valence validity.

Proposed admission bounds: at most 1 MiB input bytes, 1-128 atoms and one 3-vector
per atom. These are local resource choices, not learned model chemistry limits.
Read at most the byte limit plus one, then hash and parse the same bounded buffer;
never hash the input path separately and reopen it for parsing. A read-only mount
does not prevent a host rewrite: provenance must identify exactly the bytes used.
In contained scratch, test both an initially oversized source and one that grows
past the limit during reading, with appended bytes available before the reader
reaches EOF. Prove total consumption stays within the byte limit plus one and
oversized input is rejected before parsing. Inject a read failure and keep it an
operational error rather than classifying it as malformed user input. This applies
013 U13's consumed-work and operational-failure guidance; see its cited source
and rationale at
https://github.com/numpde/nmrnet-repro/blob/e6a8a1b1a2dd5cb854d70277f40d3275945ce933/notes/013_sibling_practices_20261016.txt#L176-L184.
Check atom counts and row dimensions before array conversion or quadratic
allocation. Reject extra fields (including
labels or selection-mask overrides), duplicate JSON object keys, unknown atom
symbols and model special tokens. Atom symbols must have dedicated ordinary
chemical-element entries in the loaded dictionary; mapping to UNK is not allowed.
Reject booleans used as numeric coordinates and nonfinite numbers. Check finite
values both before and after float32 conversion: finite JSON/float64 values can
overflow float32. Centering and distance construction must also produce finite
tensors before model execution.

Output has unit="ppm" and predictions ordered by original zero-based atom_index,
each with atom_index, element and shift_ppm. Every H/C
atom appears once; other atoms remain molecular context. Absent nuclei yield no
entries; neither H nor C yields an empty list without an empty-tensor model call.
Hydrogen completeness belongs to the caller. Identities/resource facts belong in
the adjacent receipt rather than per-prediction metadata.

===================================

Model reuse, containment and failure semantics
=============================================

The loaded scientific object owns one fixed element's model, dictionary and
scaler, and predicts that element's atoms in one molecule at tensor batch 1.
The one-shot command composes these objects: load H, predict, release H; then
load C, predict, release C. Skip an absent element without an empty model call.
Merge by original atom index and publish only after both required predictions
succeed; a C failure cannot publish the earlier H result as a successful answer.
The qualification loop instead loads H once for all qualification fixtures,
releases it, then loads C once for those fixtures, skipping absent elements.
It also exercises the composed one-shot
command; per-element callable proof alone does not qualify that command. This
permits ordinary model reuse without a public batch protocol, daemon or concurrent
model copies.

Use the existing admitted immutable inference image: both embedded dependency
declarations must match, and its upstream revision must match the recorded
submodule. Verify extraction receipts and every consumed checkpoint/scaler/
dictionary member before trusted deserialization, and ensure deserialization
consumes those same verified bytes. `baseline_prepare.verified_member` currently
checks a member and returns its path; a later path reopen leaves a replacement or
in-place write gap. Deserialize a verified immutable byte buffer or a snapshot
protected from mutation through loading. A read-only bind mount does not stop
another writer to its backing file; a held descriptor prevents pathname
substitution but permits same-inode writes. In the contained qualification lane,
simulate both changes to the source after verification; require loading to retain
the verified bytes or reject the change. This protects against concurrent source
changes within the stated container/host boundary, not a hostile host or engine
administrator. Record the identities of the exact bytes consumed. Dictionary
ordering and full state compatibility remain hard admission requirements. A
pickle from a user input path is never a supported format. Record the actual
adapter/helper bytes alongside the image,
repository/source revisions, model identities and the hash of the same bounded
input buffer consumed by the parser. This extends the local path-returning helper
contract for a specific reason; it does not establish release authenticity from
a locally computed hash alone. See 013 U05 and:
https://github.com/numpde/nmrnet-repro/blob/e6a8a1b1a2dd5cb854d70277f40d3275945ce933/tools/baseline_prepare.py#L132-L163

The launcher owns the local engine and exact container lifecycle. All project
Python/tests/probes run contained: network=none, pull=never, nonzero UID/GID,
read-only root/inputs, cap-drop ALL, no-new-privileges, two CPU quota units,
4 GiB/no swap, 64 PIDs and baseline-bounded scratch. Grant only required inputs,
tools and dedicated output; no socket/home/credentials/workspace-root/devices.
Cancellation removes only the owned container, identified by this attempt; verify
that the engine reports it terminated. Local native-helper process retirement
alone does not prove engine-side work ended. This is a cancellation acceptance
check from 013 U14, not a new daemon; see the
[helper's retirement boundary](https://github.com/numpde/nmrnet-repro/blob/e6a8a1b1a2dd5cb854d70277f40d3275945ce933/tools/inference_native.sh#L7-L10).
Future acquisition still requires explicit command-line WLAN_INTERFACE;
prediction never acquires.

Use tools/container_guard.py for the new Python entrypoints and reusable
scientific modules, checking before dependency imports or side effects. The
launcher supplies NMRNET_IN_CONTAINER=1 explicitly and mounts and hashes the
actual shared guard source with the other executed files. This prevents accidental
direct host execution; engine grants enforce containment. Do not introduce a
second detection scheme. Exercise missing-marker rejection only in contained
subprocesses. The maintained test/repository convention suite automatically
includes nmrnet_inference/ sources and enforces hierarchical Make target names;
keep this slice within that existing policy.

Missing files,
image mismatch and an existing output destination fail without replacing prior

attempt/input/model/tool identities and causal failure diagnostics. Publication
of result.json and complete.json follows existing no-clobber, fsync conventions;
complete.json is authoritative only after all required H/C outputs and identities are
verified. Abrupt termination or storage failure may prevent diagnostic retention;

Prospective parity and coverage proof
====================================

The qualification loop owns four separate single-molecule fixtures from 001's
two H and two C source records, with an explicit source-key/atom-index identity
crosswalk retained in its evidence. Those identities are not public input fields.
Before fixture iteration, assert the exact H and C source-key sets and the exact
set of 64 `(source_key, atom_index)` pairs from the pinned 001 reference; matching
the count alone can hide a substituted or omitted position. The population source
is `artifacts/reference-cpu-float32.json`, SHA-256
`8268206ad12003dea5ef57e1a7392de69325e110b54f2b91ee0f6314c4fef5ae`.
Add only the minimal cases needed where those records lack unlabelled eligible
atoms or an absent nucleus. These fixtures qualify preprocessing, output coverage
and agreement with the retained baseline; they do not establish broad chemical
accuracy.
Keep three proofs separate:

A. Tensor parity: for each original reference molecule, compare every shared
   model tensor against the real upstream dataset/collater, including float bits,
   dtypes, shapes, coordinate cast/centering order, distances, special tokens,
   edge IDs and padding. Source the oracle from verified original records. Its
   real training labels are allowed in test-only upstream preparation, never
   copied into the adapter request. Selection masks intentionally differ where
   source labels were absent; verify the production all-H/all-C mask against atom
   identities, and verify the oracle mask against original reference evidence.
   Exact shared-tensor parity is required before comparing predictions.

B. Existing-output parity: compare adapter outputs at the exact 64 labelled
   source record/atom positions with artifacts/reference-cpu-float32.json. This
   proves overlap with 001, not full output coverage. The production interface
   has no selection-mask override to make this test easier. Test-only diagnostic
   calls may compare the real upstream model at matched selection shapes, but
   such a diagnostic cannot substitute for testing the ordinary all-atom path.

C. Complete label-free coverage: independently count all supplied H and C atoms
   and assert exactly those original indices appear once, in order, with finite
   values. Include unlabelled eligible atoms and molecules with an absent nucleus;
   neither label availability nor label values may decide production coverage.
   Compare repeated independent calls and reordered fixture execution using the
   qualification crosswalk to expose leaked model state. Caller labels/target/mask
   fields are rejected, not consumed.

The `.work` run is not the only retained evidence for a published qualification
claim. After review, preserve one compact immutable observation packet at
`artifacts/prediction-cpu-float32.json`. Include the rights-cleared fixture request
bytes, source keys and raw-record hashes, derived-request hashes, exact expected
population, raw per-tensor comparison observations, complete H/C predictions and
the 64-position comparison. Bind fixture production to the exact helper and
upstream source bytes, not just repository names. Record model member identities,
image and runtime identity, numerical policy, method, and the packet producer and
purpose. Keep unreviewed logs and scratch under `.work`; publish no source data
without an established distribution basis. If fixture data cannot be included,
state the access and rerun limitation explicitly. The packet records one historical
execution and is immutable; qualification commands produce new run evidence.
Any later deterministic summary generated from that packet needs paired write and
no-write checks from the same canonical inputs under 013 U20. This evidence policy
follows 013 U06/U19 and preserves the distinction between observation and rerun.

Numerical policy must be declared and reviewed before the first adapter/reference
output comparison. Shared tensors and matched-selection model execution start
with exact equality (ATOL=RTOL=0) in the same recorded image/CPU/thread runtime.
The initial all-atom overlap comparison also uses ATOL=RTOL=0. Unlike 001's two
identical executions, selecting additional atoms changes the node-head matrix
shape, which can change floating-point rounding even with identical encoder
features. Thus exact overlap is an explicit acceptance target, not an assumed
mathematical guarantee. The owner must inspect this risk before output comparison.
If a nonzero allowance is necessary, document a focused numerical justification
from the head operations, floating-point precision and paired inverse scaler;
have it independently reviewed before adopting a different threshold. Limit this
review to the affected operations. Do not reuse 001's label roundtrip allowance
as a prediction-parity bound or choose a threshold from the
observed failing discrepancy. An unexplained failure blocks qualification;
retain it and investigate the cause rather than relaxing the test to pass.
Any revised numerical contract needs a separately reviewed rationale and fresh
qualification, with the original failed attempt preserved.
